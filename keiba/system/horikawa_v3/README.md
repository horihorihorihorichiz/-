# 堀川システム v2

発走前に分かることだけを使って、1レースの出走馬を強い順に並べる。
netkeiba から自分で材料を取り、自分で配点を学習し、自分で予想を出すところまで一式。

実測（中央競馬10,551レース・2023年8月〜2026年8月、未知期間1,707レースで1回だけ測定）:

| | 1位が1着 | 1位が3着内 | 上位6頭で3着独占 | 対数尤度 |
|---|--:|--:|--:|--:|
| 元の16成分・線形 | 23.43% | 54.66% | 37.96% | −2.2446 |
| 26成分・線形（調教込み） | 26.54% | 58.41% | 43.06% | −2.1338 |
| **50成分・木（本命）** | **27.77%** | **59.64%** | **43.94%** | **−2.0906** |
| （参考）市場＝単勝オッズ | 34.27% | 66.14% | 50.67% | −1.9169 |

**元の16成分との差（対応のある検定）**

| 指標 | 差 | t |
|---|--:|--:|
| 1位が1着 | +4.34pt | **4.07** |
| 1位が3着内 | +4.98pt | **4.00** |
| 上位6頭で3着独占 | +5.98pt | **5.50** |

3つとも規律R5の t>3.0 を越えている。

**市場には勝てていない。3通りのやり方で確かめた。**

| 試したこと | 市場条件付きの上乗せ |
|---|--:|
| 26成分・線形（条件付きロジット） | +0.0019 nats（β=−0.130, t=−4.19） |
| 50成分・木（市場を土台に固定して積む） | +0.0007 nats |
| 54成分・木（市場を土台＋市場も成分） | **−0.0010 nats（悪化）** |

単勝の控除率20%を越えるには1レースあたり 0.223 nats が要る。桁が3つ足りない。
**このシステムは「当てる」ためのもので、「儲ける」ためのものではない。**

## 入れかた

```
pip install numpy requests
cp config.example.py config.py     # 中を書き換える
```

`config.py` にログイン用の記録（クッキー）を貼る。取り方は config.example.py の中に書いた。
**この値は自分のパソコンの中だけに置くこと。誰にも渡す必要はない。**

## 使いかた

```
python -m hk.cli harvest 20230805 20260823   # 取得（着順表 約60分 → 追い切り 約4時間）
python -m hk.cli gbdt                          # 木の学習器で学習（本命）
python -m hk.cli fit                          # 線形の配点表も要るとき
python -m hk.cli check                        # 線形を未知期間で測る
python -m hk.cli predict 202605020811         # 1レース予想する
```

取得は途中で止めても、同じコマンドで続きから再開する。

### 取得の速さについて（実測でわかったこと）

- 着順表（db.netkeiba.com）は毎秒3件を1時間続けても問題なかった。
- **追い切り（race.netkeiba.com）は毎秒2件を1時間半でアクセスを止められた（HTTP 400）。**
  復旧まで数時間かかる。既定値は毎秒0.7件にしてある。**ここは上げないこと。**
- 止められた場合、`Fetcher` が自動で減速して待つ。それでも駄目なら時間を空けて再開する。

## 木の学習器について（`gbdt`）

セルを手で切るのは効かないと測定で分かった（コース単位266セルは全体1本より悪い）。
かわりに、**条件そのものを成分として渡す**。

    頭数 / 距離 / 芝ダ / 馬場 / クラス / 場 / 回り / 内外 / R / 月

これを渡すと、学習器が「ダートの短距離ならTSIを重く、芝の長距離ならDSIを重く」といった
条件ごとの使い分けを自分で見つける。手でセルを切るより壊れにくく、実際に強かった。

さらに馬ごとの生の値を14個渡す（前走着順・前走着差・通算勝率・同条件率・連続3着内・
休養日数など）。合計50成分。

`pip install lightgbm` が要る。入っていなければ線形版が動く。

## 何をしているか

1. **成分づくり** — 各馬の過去9走から23個の数字を作り、**レース内で標準化**する。
   点数はレースをまたいで比べられない（そこは元のシステムと同じ）。
2. **学習** — 上位3着までの順位そのものを目的にした順位ロジット（Plackett-Luce）。
   「1位が1着」「上位で3着内を占める」に直接効く形。
3. **階層縮小** — 全体1本 → 6群 → 場／クラス → コース単位、の4段。
   各段の縮小定数は `k = σ²/τ²` を式で解いて決める（掃引しないので規律R3に触れない）。
   件数の足りないセルは推定せず親そのものを使う。
4. **段階の自動選択** — 学習期間の内側でさらに時系列に切り、どこまで細かくすべきかを決める。
   未知期間には一切触れない。
5. **予想** — 順位・上位6頭の印・レースの形（1強〜混戦）・その形での過去の的中率・市場とのずれ。

## 成分（追い切りがあれば26、無ければ23）

| | | |
|---|---|---|
| TSI | 自前の速度指数 | 基準タイムとの差 |
| LTS | 近走着順 | 条件が合えば加点 |
| FSI | 脚質×枠 | 芝は内、ダートは差し追込が外 |
| Bonus | 実績加点 | 今回以上の格での勝ち鞍 |
| DSI | 距離適性 | 近3走±200mで掲示板 → 3段階 |
| NSI | 格 | 3着以内に入った最高クラス |
| CSI | 位置取りの安定度 | 通過順の平均とばらつき |
| WAS | 斤量 | 出走馬の中での相対 |
| TAS | 道悪適性 | 1年以内の稍重以下での着順 |
| HCS | 条件調整 | 斤量変化と格の変化 |
| NRJA | 間隔 | 前走からの日数 |
| 展開乗数 | 展開 | 逃げ先行の頭数から5段階 × 脚質 |
| spd_res | 脚の残り | 4角からの詰め＋上がり |
| mgn_abs | 着差 | 勝ち馬とのタイム差の平均 |
| wide4c | 4角外回し | 3角→4角で外へ出した分 |
| pos_gain | 位置上昇 | 1角→4角の押し上げ |
| **騎手** | 騎手の実力 | **単独で最も効く成分**。k=200で縮小、そのレースより前だけ |
| **調教師** | 調教師の実力 | 同上 |
| **前走人気** | 前走の市場評価 | 外しても対数尤度は0.0055しか落ちない |
| **馬体重** | 相対馬体重 | 出走馬の中での相対 |
| 距離変化 | 距離の延長短縮 | 前走との差 |
| **齢** | 齢 | 年齢混合戦でのみ効く（同一レース内の相対なので） |

太字が元の16成分に対して足したもの。この7つを足したことによる改善が、
測定できた唯一の本物の改善だった。

追い切りが取得できていると、さらに3つ足す（無ければ自動で23成分のまま動く）。

| | | |
|---|---|---|
| 調教縦断 | 同じ馬の過去の追い切りとの差 | **同じコース種別どうしでのみ比べる**（坂路とウッドは尺度が違うので混ぜない）。速いほど＋ |
| 調教本数 | 前走からの本数 | |
| 調教評価 | 短評を順序に直したもの | 抜群+3 〜 不安−3 |

**この3つはまだ未知期間で測れていない。** 縦断比較は文書§5-2が
「織り込み途上＝相対的に余地あり」とした唯一の項目なので、
`harvest` が通ったら `check` を1回だけ回して t>3.0 を越えるか見ること。

## 測ってわかった、効かなかったこと

- **セルを細かくしても良くならない。** コース単位266セルは、全体1本より悪い（t=−1.28）。
  6群より下は、どの切り方でも t<1.5 で誤差の中だった。
- **有料のタイム指数を足しても当てる力は変わらない。** 自前の速度指数と同じものを測っていた。
- **λ縮小の3本比較（一律0.5 / k一律 / 成分別k）は、事前試算で順位相関0.99〜1.00。**
  差が出る余地が最大2〜3ptしかなく、2.6ptの検出に9,600Rが要ることを考えると測る意味がない。

## まだ測れていないこと

- **調教（追い切り）の3成分** — 実装は入っているが、未知期間での測定がまだ。
  2026年8月にブラウザから取得を試みたところ、毎秒2件を1時間半続けた時点で
  netkeiba に止められた（HTTP 400）。その後 `db.netkeiba.com` と
  `race.netkeiba.com` の両方が半日以上 400 を返し続けた
  （`www.netkeiba.com` は正常だったので、会員としての利用には影響なし）。
  **同じ失敗を繰り返さないために、既定値は毎秒0.7件にしてある。**
- 含水率・クッション値・締切直前オッズ（データラボ側）

## 止められたときは

- 慌てて叩き直さない。`Fetcher` が自動で減速して待つが、それでも駄目なら
  数時間から半日空ける。
- `harvest` は取得済みを飛ばすので、いつ再開しても続きから進む。
- 着順表と追い切りは別ドメイン。片方だけ止まることも、両方止まることもある。
