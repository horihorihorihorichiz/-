## 1. モデル（実装前に確定）

### 1-1. 形
レース r の出走馬 i について

```
効用      u_i = o_i + x_i · θ
オフセット o_i = log(pm_i)          ← 市場。係数は 1 に固定し、学習させない
pm_i     = (1/odds_i) をレース内で合計1に正規化（控除率補正）
q_i      = exp(u_i) / Σ_j exp(u_j)   ← レース内で正規化（条件付きロジット）
```

θ=0 のとき `q ≡ pm`（＝素の市場）になる。つまり **θ は市場からの差分だけを表す**。

### 1-2. 目的関数（3着内）
台帳には3着までの**着順**があるので、Plackett-Luce（条件付きロジットの3段展開）で
「3着内に入った3頭が、その順で選ばれる」尤度を最大化する。

```
LL = Σ_race Σ_{k=1..3} [ u_{i_k} − log Σ_{j ∈ 残り} exp(u_j) ]
     （i_1,i_2,i_3 = 1着・2着・3着の馬。残り = まだ選ばれていない出走馬）
```

これは「レース内で正規化された条件付きロジット」で、目的は **3着内の並び**である。
勝ち馬当て（単勝・馬単・三連単）の判定は**一切行わない**（V4/V5/V7/V8 で4回負けているため）。

賭けに使う確率は、推定した `q` から **Harville 変換**で求める無順序の3着内確率:
```
P3_i = Σ_{j≠i} Σ_{k≠i,j} [ q_i·q_j·q_k / ((1−q_i)(1−q_i−q_j)) ] を i が1/2/3着のいずれかになる形で合算
      （実装は再帰なし・O(n^2) の標準式。市場側 P3^mkt は同じ式に q=pm を入れて計算する）
```

### 1-3. 説明変数（**4本のみ・追加禁止**）
`CORNER_PROTOCOL.md` で **MINE→VALIDATE→CONFIRM の3段すべてを通過した4本**だけを使う。
値は `corner_feats.feats()` の生値をレース内z標準化したもの（None は 0＝平均扱い）。
`CORNER_REPORT.md` と同一のコード経路・同一の as-of 規約で作る。

| # | 名前 | CORNER での通過目的 |
|---|---|---|
| 1 | `spd_res` | top3 |
| 2 | `mgn_abs` | win |
| 3 | `wide4c` | win |
| 4 | `pos_gain` | win |

**「4本が通ったから追加でこの特徴も」は禁止。5本目以降は入れない。**
もし将来増やす場合は、その時点で試行回数を記録し多重比較補正をやり直す。

### 1-4. 正則化
L2 のみ。罰則 = `λ · N_race · ||θ||²`。
**λ は MINE の内部5分割クロスバリデーション（レース単位・分割は rid のハッシュで固定）だけで決める。**
グリッド（事前確定・これ以外を試さない）:
```
λ ∈ {0, 1e-4, 3e-4, 1e-3, 3e-3, 1e-2, 3e-2, 1e-1, 3e-1, 1.0}   （10点）
```
選択基準 = 5分割の held-out 平均 LL（1レースあたり）が最大の λ。

## 3. 測定と合格ライン（事前に固定・あとで動かさない）

### 3-0. 必ず記録する測定（判定の材料）
1. **θ の符号一致**: MINE で推定した θ の各成分の符号と、VALIDATE 単独・CONFIRM 単独で
   再推定した θ の符号が一致するか（4成分それぞれ○×で記録）。
2. **真のOOS ΔLL**: MINE で推定した θ をそのまま当てた
   `ΔLL = LL(θ_MINE) − LL(0)` を VALIDATE / CONFIRM それぞれで計算する。
   `LL(0)` は素の市場（学習パラメータゼロ）なので、これは正真正銘の期外値である。
3. **α**: 追加項全体を1本のスコア `s_i = x_i · θ_MINE` にまとめ、
   各フォールド月で `u_i = o_i + α·s_i` の α を単独推定する（市場は係数1固定のまま）。

### 3-1. 一次（統計）
> **VALIDATE の OOS ΔLL > 0 かつ CONFIRM の OOS ΔLL > 0**

### 3-2. 二次（安定性）
> **α > 0 が 6フォールド（202603〜202608）すべてで成立**

### 3-3. 三次（本命・実弾相当）

> **【差し替え・2026-08-19／VALIDATE・CONFIRM を1回も走らせる前に確定】**
> 当初は「複勝ROI 100%超」を三次に置いていたが、並行して走っていたクラスタ検証
> （`CLUSTER_REPORT_20260818.md` / コミット `e1c3465f4`）が **複勝2点の構造的な天井**を実測した:
> 82クラスタ横断で `ROI = 0.726 × 的中率 + 22.5`、**的中率100%を外挿しても ROI = 95.1%**
> （的中1回あたり払戻が196〜199円しかなく投下200円を常に下回る）。
> **複勝2点で100%超は原理的に不可能**なので、三次を **三連複1点**に差し替える。
> 100%到達に必要な上積みは 複勝1点 +8.8pt / ワイド3点 +14.1pt / **三連複1点 +3.5pt(14.9%→18.4%)** で、
> 三連複だけが現実的（三連複の控除率は実測25.1%と最も高いが、必要な的中率の上積みが最も小さい）。

## 5. 事前に分かっている限界（先に書いておく）

1. 4特徴の効果量は小さい（CORNER の CONFIRM 期 真のOOS ΔLL 合計 +13.2 nats / 8,694行 = 0.0015 nats/行）。
   一次を通っても、三次（ROI 100%超）に必要な +8〜15pt を生む保証はまったくない。
2. 複勝の**発走前オッズが台帳に無い**（払戻しか無い）ため、「複勝の価格に対する妙味」で買うことはできない。
   よって買い方は「モデル確率での順位」または「モデル/市場の確率比」に限られる。
   価格を見ずに買う以上、市場が既に織り込んだ分を取り返せない可能性が高い。
3. Harville 変換は「1着の確率から3着内の確率を作る」近似で、実際の複勝配当構造とは一致しない。
4. `sgap` は V3 の得点差なので、三次判定のレース選別だけは V3 に依存する。
   これは既存の除外条件をそのまま使うという指示に従ったもので、モデル本体は V3 非経由である。
5. 三次は 5通りの探索を含む。MINE で最良の1案を選ぶ時点で選択バイアスが入るので、
   VALIDATE と CONFIRM の**両方**を条件にしている（片方だけの100%超は採用しない）。
