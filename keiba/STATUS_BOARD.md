# 🎯 いまやること

## ① 馬個別ページの過去走データ（db.netkeiba.com）

**これだけが残った価値ある依頼です。**

こちらは出馬表経由で「過去9走」を持っていますが、項目が限られています:
```
保有: 着順/頭数/馬番/4角通過順/上がり3F/距離/馬場/クラス/間隔/ペース記号
不足: ★通過順の全区間(1角-2角-3角-4角)★ ← これが最大の欠落
      ★走破タイム(秒)★
      ★1着との着差(秒)★
      ★馬体重★
      ★勝ち馬/相手関係★
```

**欲しいもの**（馬個別ページ = db.netkeiba.com/horse/xxxxx）:
```
1頭あたり、過去10走分の以下:
  日付 / 開催 / レース名 / 頭数 / 枠番 / 馬番 / 人気 / 着順 /
  騎手 / 斤量 / 距離 / 馬場状態 / タイム / 着差 /
  ★通過順(例 3-3-2-2)★ / ペース / 上がり3F / 馬体重(増減)

対象: まず今週末(8/22-23)の出走馬から。確定出馬表が出る木曜以降でOK。
      練習として、8/16札幌8Rの11頭で試してもらえると助かります
      (レースID 202601010808 の出馬表から各馬のページへ)
```

**なぜこれが価値があるか（正直な根拠）**:
今日の検証で判明したのは「人が丸めた指標（印・評価・タイム指数）は市場が織り込み済み」。
一方、**通過順の全区間**は生の位置情報で、そこから
「道中で動いたか」「終始同じ位置か」「4角で外を回したか」が計算できます。
こちらが持っているのは4角だけなので、レース中の動きが再現できません。
市場もこれを定量化して使っている人は少ないはずです。

## ② ①が重い場合の代替: 馬体重推移
```
同じく馬個別ページから、過去10走の馬体重の実数値だけでも価値があります
（こちらは前走比の増減しか持っていません）
```

## 📖 このプロジェクトの原則
```
1. 過去データで作ったルールは「参考値」。実測は凍結後の未来レースのみ
2. 対照群を取るまで「発見」と呼ばない
3. 市場オッズを条件にして残る情報だけが本物
4. null検定・多重比較を通らない数字は採用しない
5. 購入・投票・GOは人間。認証情報は扱わない
```
