## 0. 結論を先に書く（設計上の重要な訂正）

依頼文にあった仮説「**三連複は直前まで待つと配当が伸びるので T-3 で買う方が T-30 より有利**」は、
**そのままでは成立しない。** 理由は1つ:

> **中央競馬はパリミュチュエル方式で、払戻は「最終オッズ」だけで決まる。**
> T-30 に買っても T-3 に買っても、当たったときに受け取る金額は同じ（最終オッズ×100円）。
> 「買った時刻のオッズで払い戻される」のはブックメーカー（固定オッズ）の話。

したがって予備実測の「三連複 1.91倍」は **儲けの機会そのものではない**。
だがこれは **無価値ではなく、むしろもっと重要なものを意味している**:

> **判定時刻に画面に出ているオッズは、実際に払い戻される最終オッズの「偏った推定値」である。**
> 三連複で中央値1.91倍なら、T-15/T-30 のオッズで計算した期待値は **実際の期待値をおよそ半分に
> 過小評価している**（＝見送っている買い目の中に本当は買うべきものがある）。
> 逆に単勝は0.73倍なので、T-30のオッズで計算したEVは **3割ほど過大評価**（＝買ってはいけないものを買う）。

そしてもう1つ、システム全体に効く含意がある:

> `hist_odds/` に貯めた過去オッズは **すべて最終オッズ**。
> これで測ってきた ROI は「**最終オッズを見てから買い目を選び、最終オッズで払い戻される**」世界の数字。
> 実戦では最終オッズを見てから買えない。**この乖離（先読みバイアス）の大きさは、
> いままで一度も測られていない。** それを測れる唯一のデータがこの時系列である。

→ よって一次仮説は「買う時刻」ではなく **「判定時オッズ→最終オッズの写像」** に置く。

## 1. 仮説

| # | 仮説 | 棄却/採択の意味 |
|---|------|----------------|
| **H0** | 時点 t のオッズは最終オッズの不偏推定。比 r = odds_FINAL / odds_t の**レース中央値の中央値** = 1.00、かつオッズ帯によらない | ドリフトは無い。この研究は終了、他の領域へ |
| **H1a** | r の中央値が券種ごとに 1 から系統的にズレる | EV計算に**定数倍の系統誤差**がある。補正するだけでモデルを触らず改善 |
| **H1b** | ズレが「オッズ帯 × 時点 × 頭数」で説明できる | 補正関数 f(odds_t, t, n) が作れる（H1aより強い主張） |
| **H2** | 補正後EVで選んだ買い目の実払戻ROIが、補正前より高い | **実弾ルールの候補**になる。ここまで来て初めて紙上運用に載せる |
| **H3** | `hist_odds/`（最終オッズ）で測ったROIは、T-15オッズで判定した場合より楽観 | 過去の全バックテストに一律の割引が必要。**負の結果でも極めて重要** |

**H1a が棄却されたら H1b/H2 は測らない**（多重検定を増やさないため）。

## 2. データと除外規則（先に固定）

### 使うもの
- 主系列 = **JRA公式 sp.jra.jp**（`src="jra"`、1-2分毎更新）。単勝・複勝・ワイド・三連複。
- 終点 = **FINAL**（`settle` が netkeiba から取る確定オッズ）。実際の払戻の元になる値。
  - 8/18に検証: 8/16の2レース・全1,195点（単16/複16/ワイド120/三連複560×2R）で
    **JRA公式「最終」表示 と netkeiba確定オッズは完全一致**（比 = 1.000）。終点の定義に曖昧さは無い。
- 補助 = **netkeiba**（`src="netkeiba"`、`kind="nk"`）。値は遅れているが `odds_time`
  （API の `official_datetime`）に**実際の時刻**が入るので、**wall clock ではなく odds_time を軸に**
  すれば遅延ごと正しい観測として使える。主系列とは**絶対に混ぜない**（`index_rows` が分離済み）。

### 除外規則（分析前に固定）
1. **取消・除外が発生した遷移は除外**。プール全体が組み替わるのでドリフトではない。
   → `drift(..., skip_scratch=True)` が既定。出走馬集合が変わった時点対を落とす。
2. **障害レース**は本分析から除外（`jump=true` で別集計）。モデル対象外の市場。
3. **開催初日は買わない**（RULES）が、**ドリフトの測定には使う**（市場の性質の観測なので）。
   ただし買いルール（H2）の評価からは外す。
4. 両時点に**共通して存在するキーのみ**比較。片方だけにあるキーは使わない。
5. **三連複は全点そろった時点のみ**（`trio_full=true`）。`--max-axis` で間引いた時点は
   H1a/H1b の一次分析から除外（記録は残す）。
6. `ok=false` の行は使わない。

### 単位（最重要）
**独立な標本は「レース」であって「馬・組合せ」ではない。**
同一レース内の560点の三連複オッズは同じプールを共有していて強く相関する。
組合せ数をnと呼んだ瞬間に有意性は捏造になる。
→ **一次分析は「レースごとに中央値を取り、レースを1標本として検定する」**。
組合せ単位の集計（`stats` が出す n=…点）は**記述統計としてのみ**使い、検定には使わない。

## 3. 測る量（事前確定）

| ID | 量 | 出し方 |
|----|----|--------|
| **M1** | ドリフト率 r = odds_b / odds_a の分布（中央値・25/75%・r>1割合）を **券種 × 時点対 × オッズ帯(6帯)** で | `odds_timeline.py stats` |
| **M2** | 各時点の **Σ(1/オッズ)**（暗黙確率の合計）の推移 | 同上（`report_overround`） |
| **M3** | 推定誤差 median\|log r\| と、implied-prob 重み付き平均 log r | 追加実装（データ到着後） |
| **M4** | **先読みバイアス**: 同一の買いルールを (a) T-15オッズで判定 (b) FINALオッズで判定 した時の
実払戻ROIと**選択の重なり率**。払戻はどちらもFINAL（パリミュチュエルなので当然） | 追加実装（`result.payout` は settle 済み） |
| **M5** | 補正関数 f の当てはめ（log r ~ log odds_t + t + 頭数）と**週で分割した交差検証** | 追加実装 |

### M2 の意味（最も安い切り分け）
8/18の実測で、確定時点の Σ(1/オッズ) は **単勝 1.265（JRA単勝払戻率80% ⇒ 理論1.250）**、
**三連複 1.337（払戻率75% ⇒ 理論1.333）** と理論値に一致した。
つまりこの量は**その時点でプールがどれだけ「出来上がっているか」の直読み**になる。

- もし T-180 で三連複の Σ(1/オッズ) が 1.60 で、FINAL で 1.333 に落ちるなら
  → 早い時点のオッズは**全点が一律に短い**だけ。「1.91倍」の正体はただの発売初期の歪みで、
  馬券の妙味ではない。**補正は定数倍で済み、選択順位は変わらない＝H1bもH2も死ぬ。**
- Σ(1/オッズ) が時点でほぼ動かないのにドリフトが大きいなら
  → **資金が組合せ間で移動している**＝順位が入れ替わっている。ここで初めて H1b/H2 に意味が出る。

**この判定を M1 より先に行う。** これで多くの場合、初日で決着する。

## 4. 一次分析（この5つだけ。多重検定を増やさない）

| ID | 比較 | 検定 |
|----|------|------|
| **P1** | 三連複 **T-15 → FINAL**（主要仮説） | レース単位の符号検定（中央値≠1）、α=0.01 両側 |
| **P2** | 単勝 **T-15 → FINAL** | 同上 |
| **P3** | 三連複 **T-3 → FINAL**（凍結時点。paper_rank の凍結と同時刻） | 同上 |
| **P4** | 三連複 **T-30 → T-3**（発走前だけで完結する変化） | 同上 |
| **P5** | Σ(1/オッズ) の T-180 → FINAL 推移（M2） | 記述＋レース単位の対応比較 |

副次分析（オッズ帯別、複勝・ワイド、頭数別、場別、netkeiba遅延の実測）は
**一次で H1a が採択された券種についてのみ**行い、報告時に「副次」と明記する。

### プラセボ（偽陽性率の測定・RULES の null-sweep 相当）
同じ手続きを **時点ラベルをレース内でシャッフルした偽時系列**に対して回す。
偽データで同じ有意性が出るなら、その有意性は手続きの副産物。
一次の5比較すべてについて実施し、**偽陽性率を報告に併記する**。

## 5. 必要サンプル数（先に計算した）

独立単位＝レース。1開催日で **JRA 最大36レース**、1週末で **約72レース**（8/16は36R実測）。
符号検定（α=0.01 両側・検出力0.90）で、「レース中央値が1より大きい割合 p」に対して:

| 効果の大きさ p | 必要レース数 | 週末換算 |
|---|---|---|
| p=0.90（ほぼ全レースで同方向） | 18R | **0.3週末** |
| p=0.80 | 37R | **0.5週末** |
| p=0.75 | 55R | 0.8週末 |
| p=0.70 | 88R | 1.2週末 |
| p=0.65 | 161R | 2.2週末 |
| p=0.60 | 368R | 5.1週末 |
| p=0.55 | 1,483R | 20.6週末（＝実質測れない） |

平均 log 比で見た場合（効果量 d = mean(log r)/sd(log r)、同じα・検出力）:
d=1.0→15R / d=0.6→42R / d=0.4→93R / d=0.3→166R / d=0.2→372R。

**判定スケジュール（事前確定）**

| 時点 | 累積 | やること |
|------|------|---------|
| 8/22-23 後 | 約72R | **M2（Σ1/オッズ）を最優先で見る。** 定数倍で説明できるなら H1b/H2 を打ち切り、その旨を報告して終了 |
| 8/29-30 後 | 約144R | P1〜P4 の一次分析（p≥0.70 の効果ならここで決着） |
| 9/5-6 後 | 約216R | オッズ帯別（6帯 × 各30R以上）の副次分析。ここまでで H1a が出なければ **打ち切り** |
| それ以降 | — | H1a が出た場合のみ H1b（補正関数）→ H2 へ進む。交差検証は**週単位で分割** |

**H2（ROIでの検証）については正直に書いておく**: 三連複の的中率は数%なので、
ROI差5ptを検出するには数千点の実売買相当が要る。**3週末程度では絶対に決着しない。**
よって H2 の一次指標は ROI ではなく
「**補正前後で選ばれる買い目の重なり率**」と「**EV推定値の誤差（M3）**」に置く。
ROIは参考値としてしか出さない（RULES §後知恵禁止・部分集合ROI禁止に従う）。

## 6. やらないこと（RULES 準拠）

1. **部分集合のROIで「勝った」と言わない。** 必ず全レース比較で選択バイアスを外す。
2. **実弾に載せない。** H2 まで通っても、まず `paper.py` / `paper_rank.py` に
   「補正後EV」を**併記**して従来判定と並走させる。実弾は別途 RULES の基準（精算150Rで回収90%超）に従う。
3. **数字のラベル義務**: 本件で出る数値は当面すべて **[ライブ実測・n=…]**。
   窓内採掘の数字と混ぜない。
4. **収集が不完全な日を隠さない。** 取り逃した時点は `stats` の「時点別」件数に素直に出る。
   欠測が特定時点に偏った日は、その日を一次分析から外して理由を記録する。

## 7. 実行コマンド

```bash
cd keiba
# 収集（当日・詳細は ODDS_TIMELINE_NOTES.md §5）
python3 odds_timeline.py watch                 # 当日のJRA全レース
python3 odds_timeline.py settle                # 終了後: 確定オッズ+着順+払戻を追記

# 分析
python3 odds_timeline.py stats                              # 事前登録の主要比較
python3 odds_timeline.py stats --pair T-15:FINAL --min-n 20 # P1/P2
python3 odds_timeline.py stats --src netkeiba               # netkeiba系列(遅延込み)
python3 odds_timeline.py stats --src any                    # 両ソース(tagに@srcが付く)
```
