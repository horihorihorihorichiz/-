# 自動予想→期待値判定→自動入力 プレイブック（Ver.99.27）

目的: レースデータを渡すと、Ver.99.27エンジンで分析→期待値(EV)で「買う/見送る」を機械判定→買うなら買い目を組んでi-PATに入力(確認画面で停止)まで自動化する。

## パイプライン
```
① データ取得   Chrome/ローカルClaudeがnetkeibaを読む(馬柱9-10走+タイム指数+馬場+馬体重+最終オッズ)
② 予想        build_<race>.py を作り calc.py(STEP0-10)で 全頭得点・Final_PWin を算出
③ オッズ取得   NAR: odds_get_form.html / JRA: api_get_jra_odds.html (type1単/4馬連/5ワイド/7三連複)
④ EV判定(GO/NO-GO)  buylist.screen() で「妙味あり」か機械判定 ← 本テンプレの肝
⑤ 買い目      GOなら buylist.allocate() でEV×250%floor×100円単位のポートフォリオ
⑥ 入力        i-PAT入力フォーマットで出力 → Chrome/ローカルClaudeが通常投票に入力→確認画面で停止
⑦ 購入        人間が金額・点数を確認して購入ボタンを押す（既定）
```

## GO / NO-GO 判定（「期待値が高いレース」だけ買う）
buylist.screen(pwin, odds..., budget, floor) が返す判定。GO条件（すべて満たす）:
1. **エッジ**: モデル1位馬の 単勝EV ≥ 150%（＝人気以上に強い過小評価）、
   または モデル上位2頭のいずれかが 単勝EV ≥ 180%。
2. **回収期待**: allocate() で組んだポートフォリオの 期待回収 ≥ 130%。
3. **フロア成立**: 全点が floor(既定250%) を満たして予算内に収まる。
NO-GO（見送り）条件のどれかで即見送り:
- モデル1位＝市場1人気 かつ その単勝オッズ<3.0（旨みなし）。
- どの券種もEVプラス点が乏しく期待回収<130%。
- 頭数が少なく妙味が出ない/データ欠損が大きい。

## 予算・配分（RULES.md準拠）
- 1レース既定 10,000円 / 250%floor / 100円単位 / 単勝・馬連・ワイド・三連複(EVプラスのみ)。
- 1日の上限(任意): DAILY_CAP を決め、GOレースへ配分。超えたらEV高い順に採用。

## 自動購入の安全モード（重要）
- **既定=確認停止モード**: 入力後、確認画面で必ず停止し合計/点数を報告→購入は人間。
- **フルオート(任意)**: 明示的に有効化した時のみ。必ずハードキャップ内で:
  - 1レース上限・1日上限を超えない / floor成立点のみ / 期待回収≥閾値。
  - それでも初回は必ず人間が数レース見て検証してから。
- ログイン情報はローカル専用ファイルのみ(ipat_secret.local, .gitignore済み)。チャット/外部へ出さない。

## 実行の入口
- ローカルClaude Code(リポジトリ+Python)で: データ→build_*.py→calc→buylist.screen/allocate→i-PAT入力ブロック生成。
- Chrome拡張のClaudeが: netkeiba読み取り＆i-PAT入力を担当。
- 判定・配分の数値ロジックは buylist.py に集約(人はGO/NO-GOと合計を確認)。
