## §0 目的（2026-08-22ユーザーと合意・すべてに優先）

**目的はただ一つ: 競馬で勝つ（プラス収支で終わる）。**
検証規律・発火なし=見送り・紙上運用は、すべてこの目的の手段であって目的ではない。
「よく当たる」と「勝てる」は別物（的中83.7%でもROI91.8%=負け）。本システムが
『買い目』として送るのは「勝てる」証明があるものだけ。守りの規律は
「負ける球を打たなければ、勝てる球が来たとき全額張れる」ための攻めの姿勢である。
エッジ候補が全滅したら「待て」で誤魔化さず、次の情報源を設計する（§8参照）。

## §2 エンジン構成（これが全体・これ以外に系統は無い）

```
起動検査 selfcheck.py（ALL GREENまで作業開始しない）

   ↓
```

- 当てにいく参考枠の型は形で選ぶ: 1強→複勝1位 / 2強→ワイド1-2 / 3強→三連複123 /
  混戦→見送り。点数は常に最少（1点>2点>3点の実測順）。

## §3 毎日の運用フロー

**ユーザーの役割（2026-08-22指示で確定）: LINEに届いた【S/A】買い目を買う。それだけ。**
届かなければ何も買わない。判断・監視・起動はすべてシステム側（週末ルーチン=ROUTINE.md冒頭）。

**開催日（土日・地方開催日）**
1. 6:30 JST: `keep_alive.sh` 番人経由で `odds_timeline watch` 起動（最優先・G2判定の弾薬）。
2. `python3 selfcheck.py` → ALL GREEN確認。
3. `day_board.py` でデイボード生成 → plus_engine で発火判定。
4. 発火あり→即LINE（§4書式）。発火なし→静粛（レースごとの連絡はしない）。
5. 全レース確定後: 精算 → **デイダイジェスト1通**（発火数・当てにいく枠の結果・収集状況）。
6. MEMORY.md追記（確定・棄却・変更があった場合のみ）→ commit/push。

**非開催日**
- `pick_races.py --ev` 相当の事前スキャンは**発火表が空の間は省略可**。
- 収集済みデータの検証・9月判定の準備のみ。新しい採掘は§6の手続きなしに始めない。

## §4 通知プロトコル（凍結書式・変更は§9のみ)

- **買い目（発火時のみ）**: `場R / 券種 / 買い目 / 金額 【S or A】根拠`
  - 【S】独立した検証済み根拠が2つ以上、同一レース・同一買い目で噛み合った最大級 = **20,000円**
  - 【A】検証済み根拠が1つ成立 = **10,000円**
- **発火ゼロの日**: デイダイジェスト1通のみ。
- **恒久禁止**: 期待値プラスの証明が無いものを「買い目」として送ること。
  当てにいく枠は必ず `[参考・期待値負]` ラベルを付ける。
- 経路: LINE Messaging API（line_notify.py / トークン=line_token.local、
  コンテナリセットで消える→ユーザーに再設定を依頼する）。

## §7 検証規律と禁止事項（MEMORY.md §4と同一・再掲）

- **R1** 書き出した配点は verify_export で機械検証するまで使わない。
- **R2** null は実データと同じ自由度（同じ混合・セル数・選択幅）。
- **R3** 掃引したら「最良を選ぶ手続きごと」null で再現。勝者は新データ測定まで未確定。
- **R4** 上乗せは必ずSE併記。1SE未満を「明確」と書かない。
- **R5** 掃引の評価はDSR＋PBO(CSCV)。PBO>30%は棄却。新ファクターのt値ハードルは3.0。
- **R6** 回収率はブロックブートストラップで区間推定。判定は低分散券種(本命複勝)優先＋効果量を事前定義。
- **R7** 分割はpurged k-fold+embargo/CPCV。特徴量は発走前に入手可能なもののみ(リーク厳禁)。
- 禁止: 単勝120倍超 / 三連複BOX手広 / 18頭乖離系 / モデル確率×オッズの期待値 /
  期待値負を「買い目」として送る / 穴軸の組合せ券種（§1で最悪と実証）。
- セキュリティ（変更禁止）: 購入・投票・GOは人間 / 認証情報を扱わない・保存しない /
  netkeibaにログインしない / 結果は確定後のみ記録。
