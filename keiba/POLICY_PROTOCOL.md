# POLICY_PROTOCOL — レース単位の行動方策を1本の浅い木で学習する（事前登録）

登録日時: 2026-08-20（測定前に本ファイルを確定。以後の変更は行わない）
実装: policy_tree.py（本プロトコルの機械実行。乱数はseed固定）
データ: bsd16_races.jsonl（8,002R。全レースに全券種払戻・全頭オッズ・fav_p/ent/sgap16あり＝確認済み）

## 1. 問い

「レース特徴 → 7行動のどれを取るか」を深さ<=3の1本のCART様の木として MINE で学習したとき、
その方策ごと VAL/CONF に汎化するか。判定はヌル統制（ラベルシャッフル100回）との比較で行う。

## 2. データ分割（不変）

- MINE: month <= 202602（学習・全決定はここだけ）
- VALIDATE: 202603–202605（最後に1回だけ評価）
- CONFIRM: 202606–202608（最後に1回だけ評価）

## 3. 行動空間（固定・7個。1レースにつき1行動）

各行動の掛け金は100円/点。払戻は bsd16_races.jsonl の payout（100円あたり）をそのまま使う。

| # | 行動 | 買い目 | 点数(=掛け金/100円) |
|---|---|---|---|
| A0 | 見送り | なし | 0 |
| A1 | 複勝市場2点 | 市場人気1位・2位（単勝オッズ昇順、同値は馬番昇順）に各1点 | 2 |
| A2 | 複勝モデル1点 | B-sd16 rank16[0] に1点 | 1 |
| A3 | ワイド市場1-2 | 市場人気1位-2位の1点 | 1 |
| A4 | ワイドB-sd16上位2 | rank16[0]-rank16[1] の1点 | 1 |
| A5 | 三連複市場4BOX | 市場人気1〜4位のBOX（C(4,3)=4点。field<4なら成立せず=見送り扱い） | 4 |
| A6 | 三連複B-sd16 2軸流し | rank16[0],[1]を軸、相手=rank16[2..5]（fieldが小さい場合はある分だけ。min(4, field-2)点） | ≦4 |

- 的中判定は payout 辞書のキー照合のみ（複勝=馬番、ワイド=昇順ペア、三連複=昇順トリプル）。
- 同着で複勝が3頭超払われるレースもそのまま辞書照合（データに存在する形をそのまま使う）。

## 4. 特徴（発走前に入手可能なもののみ・固定8個）

1. fav_p（1番人気の正規化implied確率）
2. ent（オッズimplied分布のエントロピー）
3. sgap16（B-sd16スコア1位-2位差）
4. field（頭数）
5. fav1_odds（単勝1番人気オッズ = min(odds)）
6. tier（{3,4,5,6,10}を序数として扱う）
7. surf（0=芝, 1=ダ）
8. dist（0=S, 1=M, 2=L）… surf/distはsd文字列から分解

## 5. 学習手続き（MINEのみ・決定的）

貪欲な深さ<=3の二分木（CART様）。分割候補は各ノード共通の固定グリッド:

- fav_p / ent / sgap16 / fav1_odds: MINE全体の10%〜90%分位点（9本ずつ）
- field: t ∈ {7,9,11,13,15,17} の「field <= t」
- tier: t ∈ {3,4,5,6} の「tier <= t」
- surf: 「surf <= 0」（芝 vs ダ）
- dist: t ∈ {0,1} の「dist <= t」

計49候補/ノード。

- リーフの行動 = リーフ内MINEでのROI最大の行動。ただし最大ROIが100%以下なら A0見送り。
  （ROI = 総払戻/総掛け金。A0のROIは定義上100%とみなす）
- ノード価値 V(node) = そのノードにリーフ行動規則を適用した時の利益（総払戻-総掛け金。見送り=0）
- 分割の採否: gain = V(left)+V(right)-V(node) が正で最大の候補を採用。
  タイブレークは特徴の上記列挙順→閾値昇順。gain<=0 なら分割せずリーフ化。
- 制約: 深さ<=3（最大8リーフ）、min_leaf = 300（MINEレース数）。両子が300以上の分割のみ許可。
- 分位点計算を含め全てMINEのみ。乱数不使用（決定的）。

## 6. 評価（VAL/CONFは最後に1回だけ）

学習済みの木を VAL / CONF の各レースに適用し、
- 賭けたレース数 n_bet、総掛け金、総払戻、ROI、利益（円）、見送り率
を券種内訳付きで1回だけ算出する。

## 7. ヌル統制（必須・100回）

- 各レースの「7行動の(掛け金,払戻)ベクトル」を事前計算し、**MINE内でレース間シャッフル**
  （特徴は元のレースに残す。ラベル=結果だけ入れ替える）。seed = 0..99 の100回。
- 各回、§5と同一の手続きで木を学習し、得られた偽方策を**本物のVAL（およびCONF）**に適用。
- 統計量: 偽方策のVAL ROI（掛け金0の回はROI未定義として除外し、除外数を報告。
  併せて常に定義される利益(円)の分布も報告）。
- **判定基準（主）**: 実方策の VAL ROI > ヌルVAL ROIの95%点 かつ CONF ROI > ヌルCONF ROIの95%点。
- **判定基準（実弾水準）**: 上に加え VAL/CONF両方 ROI>100% かつ 各期 n_bet>=80。
- 利益(円)でも同じ95%点比較を副次報告する（ROIが未定義になる回への頑健性確認）。

## 8. 試行数の申告

- 事前登録した方策学習は **1回**（木は1本。内部の分割探索49候補×最大7ノードは
  ヌル統制が同一手続きで再現するため、偽陽性率はヌル比較で吸収する）。
- VAL/CONF の評価は本物1回＋ヌル100回のみ。追加のグリッド変更・再学習・再評価はしない。
- 事後にパラメータ（min_leaf、深さ、分位グリッド）を動かした場合は、その結果を本審査に使わない。
