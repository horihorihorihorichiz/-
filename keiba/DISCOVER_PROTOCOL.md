# DISCOVER: 生データからの機械的特徴発掘 事前登録（2026-08-21・測定前に確定）

**目的**: これまでの検証は全て「人が設計した成分の配点調整」だった。本件は逆で、
**過去走の生の列から演算子の組み合わせで候補を大量自動生成し、データ自身に共通点を探させる**。
人の直感で候補を選ばない。生成規則を先に凍結し、そのまま全数を検定する。

本書は測定を1行も実行する前に確定した。以降**一切変更しない**（変更した場合は結果を無効とする）。

## 2. 段階1: 候補の機械的生成（生成規則を凍結）

### 2.1 過去走1走から作る「対象列」（30本・固定）
`corner_all` は**末尾が最終コーナー**（`corner4` と一致することを実データで確認済）。
末尾から `cL`(4角) / `cL1`(3角) / `cL2` / `cL3`、先頭を `cfirst` とする。

`fin`(着順), `fin_rate`(着順/頭数), `uma_rate`(馬番/頭数), `agari`(上がり3F), `run_time`(走破タイム),
`spd`(距離/走破タイム), `margin`(着差秒), `mgn_abs`(|着差|), `pace_first`(前半3F), `pace_last`(後半3F),
`pace_diff`(前半−後半), `agari_ratio`(上がり3F/走破タイム),
`cL_rate`, `cL1_rate`, `cL2_rate`, `cL3_rate`, `cfirst_rate`(各通過順/頭数),
`move_last`((3角−4角)/頭数), `move_all`((初角−4角)/頭数), `move_mid`((cL2−cL1)/頭数),
`c_sd_rate`(通過順の標準偏差/頭数), `unlucky`(着順率−4角位置率),
`days`(間隔), `dist`(距離), `tier`(クラス), `baba_idx`(馬場), `field`(頭数), `vg`(コース格),
`win`(1着フラグ), `top3`(3着内フラグ)

### 2.2 集計 × 窓（固定）
- 集計: `last`(直近1走), `mean`, `median`, `max`, `min`, `std`, `slope`(新しいほど大きい向きの回帰係数)
- 窓: `last` は直近1走のみ。他6集計は `W ∈ {3, 5, 9}`
- → 30列 × (1 + 6×3) = **570本**

### 2.3 条件付き集計（固定・平均のみ・窓9）
当該レースと「同じ条件」の過去走のみに限定した平均。
- `sameSurf`(同じ芝/ダ) / `sameDist`(距離差±200m以内) / `sameBaba`(良 vs 道悪の別が同じ) /
  `classGE`(当該レース以上のクラス＝`tier_past <= tier_today`)
- → 4条件 × 30列 = **120本**

### 2.4 レース内相対化の別型（固定）
既定は全候補を**レース内zスコア**にする（§2.6）。加えて `last / mean3 / mean5 / mean9` の4集計については
**レース内順位パーセンタイル**版も作る。
- → 30列 × 4 = **120本**

### 2.5 差分・交互作用（固定）
- `mean3 − mean9`（直近と長期の差＝トレンド）: 30本
- `last − mean5`（直近1走の突出度）: 30本
- → **60本**

### 2.6 標準化（必須）
全候補は**レース内で標準化**する（絶対値はクラス・馬場・距離で意味が変わるため）。
- z = (x − レース内平均) / レース内標準偏差、**±3にクリップ**。
- 欠測馬は 0（＝レース平均）を入れる。標準偏差が 0 のレースは全馬 0。
- 順位パーセンタイル型は (順位−1)/(頭数−1) を 0.5 中心に置き、同じくレース内で z 化する。

### 2.7 事前フィルタ（MINEのみで判定）
- MINE の馬行のうち**元値が非欠測の割合 < 40%** の候補は検定前に落とす（落とした本数を報告）。
- MINE で分散が 0 の候補も落とす。

**候補総数は生成後に実測して報告する**（上記規則から機械的に決まる値であり、後から足さない）。

## 3. 段階2: 市場を条件にした増分検定（一次基準）

各候補 1本ずつ、**市場log-oddsをオフセットに固定した条件付きロジット（top3 = Plackett-Luce 3段）**:

```
score_h = log p_market_h  +  β · x_h        （p_market = 単勝オッズ逆数のレース内正規化）
```

- β のみを MINE で最尤推定（Newton法・解析的Hessian）。
- **ΔLL = LL(β̂) − LL(0)**（nats・MINE合計）と **z = β̂ / SE** を測る。
- 市場が既に知っていることは β̂→0 に落ちるので自動的に脱落する。ROIより先にこれを見る。

**MINE通過基準（多重比較補正込み・事前登録）**:
両側 α = 0.05 を候補総数 N で Bonferroni 補正した閾値
`|z| >= z_crit`, `z_crit = Φ⁻¹(1 − 0.025/N)`（N は §2.7 通過後の実測本数）。

## 4. ヌル検査（必須）

MINE の各レース内で**着順（1〜3着の並び）をシャッフルした偽データ**を作り、
**同一パイプライン（同じ候補全数・同じ閾値）**で発掘をやり直す。seed = 20260821, +1, +2 の**3回**。

- 偽データでの通過本数の平均 `E_null` と最大 `M_null` を報告する。
- **実データ通過数が `M_null` を超え、かつ `3 × E_null` を超えない限り、発掘全体を棄却する。**

## 5. 段階3: 生き残りを束ねて加点にする

1. MINE通過候補を |z| 降順に並べ、**MINEでの相関 |ρ| >= 0.8** なら後発（|z|が小さい方）を落とす（多重共線性除去）。
2. 残りを**同時に**、市場log-oddsオフセット固定・**L2正則化つき**の条件付きロジットで MINE 学習。
   λ は MINE を時系列で 80%/20% に割った内部分割で選ぶ（グリッド `[3e-4, 1e-3, 3e-3, 1e-2, 3e-2, 1e-1]`）。
3. **既存 B-sd16 に追加する形**で組む（置き換えない）。
   `score = S_Bsd16(既存の凍結配点をそのまま使用) + Xnew · v`、**v のみ MINE で学習**（同じλグリッド、
   オフセット = S_Bsd16、L2）。既存ファイル・既存配点は1行も変更しない。

## 6. 段階4: 判定（VALIDATE / CONFIRM は各1回だけ）

**一次（これが本命）**: MINEで確定した係数をそのまま当てた**真のOOS**で、
市場オフセット条件付きの ΔLL が **VALIDATE と CONFIRM の両方で正**。

**二次**: 複勝1点 / 複勝2点 / ワイド(上位2頭1点) / 三連複(上位3頭1点) の的中率とROIを MINE/VAL/CONF の3期で並べる。

**合格ライン（事前登録・これを満たさなければ不合格と書く）**:
> VALIDATE と CONFIRM の**両方**で、B-sd16 より**複勝的中率が +2.0pt 以上**（複勝1点・複勝2点の両方で判定し、
> どちらか一方でも未達なら未達と書く）、**かつ どちらの期も ROI が B-sd16 を下回らない**。

惜しい数字を格上げしない。未達は未達と数字で書く。
