## 0. 問い

ユーザー仮説:「**コース単位（場×馬場×距離の具体値。例: 東京芝2000m）の専用システムを作れば期待値プラスになる**」

先行実験との差:
- `SPECIALIST_REPORT_20260817.md` … 1着 × 粗いセグメント（場/馬場×距離帯/クラス/頭数）→ 11中10で不成立
- `PLACE_SEG_REPORT.md` … 3着内 × 粗いセグメント（場10/馬場×距離帯6/場×馬場20）→ 二次基準通過 0/36
- **本実験** … 1着 と 3着内 の両方 × **コース単位（場×馬場×距離の具体値）** × **3方式**（素朴・階層・重み付け）

## 1. 前提となる制約（実行前に実測済み・報告書にも明記する）

台帳 `wf_ds_cache_v8.pkl`（7,699R・202307〜202608）を 場×馬場×距離 で割ると:

| 指標 | 値 |
|---|---|
| 全コース数 | **122** |
| 100R以上 | **28** |
| 20R未満 | **41** |
| 最大コース | 中山ダ1800 = **330R**（全体の 1/23） |

ユーザー指示の「100R以上ある18コース」は 5,990R台帳（`wf_preds_v3ext2.jsonl`・202409〜）基準の数。
本実験は**より長い 7,699R 台帳**を使うため、同じ「100R以上」ルールで **28コース**になる。
試行数が増える＝多重比較の分母が増える方向なので、判定は厳しくなる（緩和ではない）。

**素朴なコース専用学習はデータ不足で負ける可能性が高い**という前提を、方式1のベースラインで実測する。

## 2. データ・特徴・ハイパーパラメータ（全方式で共通・事後変更禁止）

- データ: `wf_compare.load_ds(v8=True)` = **7,699R / 106,991頭行**（202307〜202608）。
- 特徴: **50本**（V3 28 + V8 22）= `fit_place.PLACE_VARIANTS["v8place"]` の特徴指定
  （`fit_v2.build_row(r, n, v4=False, v8="f1,f2,f4")`）と1バイトも同じ。
  `build_row` は純関数なので全行を一度だけ作って `course_cache.npz` に固める（計算量対策のみ。値は不変）。
- 学習器: LightGBM。`fit_place.BIN_PARAMS` をそのまま使用
  （objective=binary / lr 0.02 / num_leaves 31 / min_data_in_leaf 30 / feature_fraction 0.8 /
  bagging 0.8@1 / lambda_l2 5.0）、`num_boost_round=800`、**early stopping 60**（学習データ末尾10%
  ＝レース単位・最低50レースを検証に使用。`fit_place.train_place_fold` と同一手順）。
  - **【2026-08-18 実行前の修正・記録】** 検証分割は **「末尾10%・最低10レース」** に変更する。
    当初の「最低50レース」だと、100〜300Rしか無いコース内学習で学習データの半分が検証に取られ、
    **方式1/2 を構造的に不利にする**（＝比較の公平性を壊す）。GEN 側は10%規則が支配するので
    実質同一だが、完全に揃えるため GEN も新規則で学習し直す。
    **この修正は方式1/2/3 の結果を一切見る前に行った**（GEN のfold進捗ログのみ確認した段階）。
  - 学習レース数が検証分割数以下で分割できない場合は**学習せず GEN を流用**し「分割不能ガード」として件数を記録する。
- 目的変数2種:
  - **PLACE**: 3着内=1 / 圏外=0
  - **WIN**: 1着=1 / それ以外=0
- 方式間で違うのは「**学習データの絞り／重み／特徴に汎用スコアを足すか**」だけ。

## 4. 比較する4本（3方式）

| 記号 | 方式 | 学習データ | 特徴 | 備考 |
|---|---|---|---|---|
| **GEN** | 汎用（基準） | m より前の全レース | 50本 | 全方式の比較相手 |
| **M1** | 方式1 素朴 | m より前の**当該コースのみ** | 50本 | データ不足の直撃を測る |
| **M2** | 方式2 階層 | m より前の当該コース（fold月202403以降に限る） | 50本 + **GENのOOSスコア1本** | 薄いモデル（下記） |
| **M3w3 / M3w10** | 方式3 重み付け | m より前の全レース | 50本 | 当該コース行の `sample_weight = 3 / 10`、他は1 |

- **M2 の薄いモデル**（事前登録・事後チューニング禁止）:
  BIN_PARAMS をベースに `num_leaves=7 / min_data_in_leaf=40 / learning_rate=0.05 / lambda_l2=10`、
  `num_boost_round=300`・early stopping 30。特徴の最後に **GEN が同じfoldで出したOOS確率**を1本足す。
  学習行の GEN スコアも「その行の fold月の GEN 予測」（＝常に out-of-sample）を使う。
  → M2 の学習対象は GEN の予測が存在する fold月（202403以降）に限られる。この非対称は限界として報告する。
- **フォールバック規定**: M1/M2 は当該コースの学習レースが **30R未満**なら学習せず **GEN をそのまま出力**し、
  「専用不能（汎用流用）」として件数を記録する。
- **計算量による範囲限定（事前登録）**: M3 は全データ再学習が1本あたり数十秒〜数分かかるため、
  **評価窓の6fold（202603〜202608）のみ**実行する。M3 の MINE窓の数値は「無し」と報告する。
  M1/M2/GEN は30fold 全部を実行する（MINE窓はデータ量分析に使う）。

## 5. 指標

同一レース集合・同一市場側で、モデル側の列だけ差し替えて比較する。

1. **α（市場を条件にした付加情報）** … 主指標
   - PLACE: `P(3着内_i) = σ(α·logit q_model_i + β·logit q_market_i + c)`
     q_model = モデル出力をレース内で和3に正規化（`place_eval.norm_place`）、
     q_market = 確定単勝オッズ → 控除率補正 → Harville で和3（`place_eval.market_probs`）。
   - WIN: `P(1着_i) = σ(α·logit p_model_i + β·logit p_market_i + c)`
     p_model = モデル出力をレース内で和1に正規化、p_market = (1/オッズ) を和1に正規化。
   - 推定は `place_eval.fit_logit` / SE は `place_eval.cluster_se`（レース単位クラスタ）。
   - **Δα = α_method − α_GEN**（同一レース集合）。
2. **単勝flat ROI** … 二次基準。モデルスコア1位に100円/レース。払戻は台帳の実払戻（無い場合はオッズ×100）。
3. **複勝flat ROI・的中率・n** … 参考（合否に使わない）。
4. **データ量との関係** … コースの学習レース数 と Δα / ROI の関係（散布・相関）。

## 6. 判定基準（事前登録・変更禁止）

### 6-0. 判定対象
- 対象コース = 台帳で **100R以上の28コース**。
- **各コースの VALIDATE / CONFIRM のレース数を必ず記録**し、
  **VALIDATE n<15 または CONFIRM n<10 のコースは「判定対象外」**として明記する（前回の設計欠陥への対処）。

### 6-1. 一次（付加情報）
そのコース・その方式・その目的で
- **VALIDATE窓全体の Δα > 0**、かつ
- VALIDATE の各月のうち **そのコースのレースが10R以上ある月**すべてで Δα > 0
  （該当月が0〜1個しか無い場合は窓全体の判定のみ。何個で判定したかを表に記録する）。

### 6-2. 二次（実弾指標）
- **単勝flat ROI: VALIDATE ≥110% かつ CONFIRM ≥100%**（n≥15 / n≥10）。

### 6-3. 総合
**総合通過 = 一次 かつ 二次**。一次だけの通過は「不成立」と報告する（PLACE_SEG と同じ扱い）。

### 6-4. 多重比較
- 試行数 = 実際に実行した (コース × 方式 × 目的) の数。
  最大 28コース × 4本（M1/M2/M3w3/M3w10） × 2目的 = **224試行**
  （M3が上位コース限定になった場合は実行数で数え直す。ユーザー指示の 18×3×2=108 は
  コース数と方式本数の数え方が違うだけで、扱いは同じ）。
- **偶然期待**:
  - 一次: 1試行あたり `0.5^(1 + 判定に使った月数)`（符号がコイン投げという帰無仮説）。
  - 二次: **モンテカルロ**で推定する。各コースについて「情報ゼロ＝各レースで一様ランダムに1頭選ぶ」
    試行を **2,000回**反復し、`VAL ROI≥110% かつ CONF ROI≥100%` になる割合 p_c を求める。
    偶然期待 = Σ_c (そのコースで実行した試行数 × p_c)。
  - 総合の偶然期待 = Σ_c (実行試行数 × p_c × 一次の偶然確率)（独立仮定・上限として二次単独の期待も併記）。
- **合否: 総合通過数 < 3 × 偶然期待 なら全体不合格**（ユーザー指示どおり）。

## 7. 既知の限界（実行前に宣言）

1. **データ量が絶対的に足りない**（§1）。最大コースでも330R・VALIDATE窓では1コース10〜40R。
   単勝flat ROI の標準誤差は n=30 で ±50pt 規模あり、二次基準は運の要素が大きい。
   → だから「通過数 vs 偶然期待」でしか判断しない。
2. **市場側は確定単勝オッズ**（発走直前の実オッズではない）。PLACE系実験と同じ限界。
   複勝の市場側は Harville 近似であり事前複勝オッズではない。
3. **M2 の学習対象期間が M1/M3 より短い**（GEN の OOS スコアが必要なため 202403以降）。
4. **M3 は評価窓6foldのみ**（計算量）。MINE窓の比較は M1/M2 のみ。
5. **スピード指数などの較正定数は全期間フィット**（既存パイプラインの軽微リーク）。
   全方式に共通なので比較の公平性は保たれるが、絶対ROIはライブ比で楽観側。
6. **収穫が2022年まで拡張中**。本実験は 2026-08-18 時点の 7,699R 台帳で確定する。
   データが増えた後の再実行は**別の事前登録書**で行う（同じデータで基準を変えて再挑戦しない）。
7. **α の窓推定はコース内で入れ子ではない**（VALIDATE窓・CONFIRM窓は互いに素なレース集合）が、
   月次のサブ判定は同一窓内のため独立ではない。偶然期待の計算はこの点で楽観側になりうる。
