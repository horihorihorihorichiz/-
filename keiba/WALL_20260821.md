# 壁の地図 — どこまでなら行けて、どこから先が無理か（2026-08-21 実測）

「加点方式を入れたらいける」という指示から始めて、加点ルールを40本作り、
実払戻で全部測った結果、**加点方式そのものより先に、壁の正確な位置が確定した**。
この文書はその地図。全部このリポジトリのスクリプトで再現できる。

---

## 0. 一行でいうと

**選び方を良くすれば ROI は 70% → 95〜99% まで上がる。これは本物。
だが 100% の線は、JRAの全馬券・全値段帯・NAR含め、どこでも越えられなかった。**

越えられない理由も分かった。歪み（本命が安すぎ・大穴が高すぎ）は確かに存在するが、
**その大きさが控除率の 2/3〜3/4 しかない**。方向は合っているが量が足りない。

---

## 1. 今日ひっくり返した自分の所見（先に訂正）

前回「市場は直近負けている馬を過小評価している（実際の3着内率 ÷ 市場想定 = **1.535**）」と報告した。
これは**間違い**だった。市場想定を単勝オッズ→Harville近似で作っており、
Harvilleは大穴の3着内率を構造的に過小評価する。近似の癖を市場の歪みと読み違えていた。

実払戻でベタ買いして測り直した結果（`rule_roi.py`）:

| ルール | 複勝ベタ買いROI | M/V/C |
|---|---|---|
| 直近3走すべて着外(6着以下) | **68.9%** | 69 / 72 / 68 |
| 前走10着以下 | 64.6% | 63 / 69 / 70 |
| 前走3着内 | 77.8% | 78 / 78 / 78 |
| 【全馬平均】 | 72.0% | |

負け馬は全馬平均より**低い**。1.535 は消えた。

ただし**オッズ帯を揃えて測ると話が戻る**（`odds_band.py`）。生ROIが低いのは大穴だからで、
同じ値段の馬と比べれば市場は負け馬を安く売っている:

| 残差 | ルール |
|---|---|
| **+6.49pt** | 直近3走すべて着外(6着以下) ← 最大 |
| +3.17pt | 格上げ後も3着内が2走以上 |
| −2.36pt | 前走3着内 |
| −2.50pt | 直近3走すべて掲示板(5着内) |

つまり所見の**向きは正しく、大きさが1桁違った**。+6.5pt であって +53% ではない。
そして 40ルールの複勝ROIは log(平均オッズ) だけで **R²=0.761** 説明できる。
ルールの大半は「人気馬を多く含むか」の言い換えに過ぎない。

## 3. 期待払戻を直接予測して買う（`ev_bet.py` / `ev_bet2.py`）

馬を並べ替える（順位モデル）のをやめ、**1頭ごとに「複勝100円は平均何円返るか」を回帰**して、
100円を超える馬だけ買う設計に変えた。控除率を超える唯一の道＝市場の価格ズレを突く、そのもの。

特徴量67本 = オッズ帯14 + 加点ルール40 + tier5 + Ver.99.27得点 + モデル順位 + 1位との差
+ 市場implied + **モデルと市場のズレ(div)** + 頭数 + log(オッズ)。MINE 89,326頭で学習。

| 上位 | | MINE（**在サンプル**） | VALIDATE | CONFIRM |
|---|---|---|---|---|
| 15% | 単勝 | 94.3% | 82.9% | 113.4% |
| 4% | 単勝 | 98.7% | 95.2% | 138.9% |
| 15% | 複勝 | 86.4% | 82.7% | 84.4% |
| 2% | 複勝 | 89.5% | 92.9% | 99.2% |

ベタ買い70.3%→94%。**+24pt は本物**。だが CONFIRM の 113〜139% は運。3つの理由で断定できる:

1. **在サンプルが100%を超えない。** 89,326頭に係数を合わせ、過学習を許した盤面ですら94%。
   学習したデータで勝てないものが未知データで勝てるはずがない。
2. **VALIDATE 82.9% と CONFIRM 113.4% が同一モデル・同一閾値で30pt食い違う。** 合算96.4%。
3. **null control**（ルールとモデル得点を無関係な馬のものに差し替えた偽モデル）も
   CONFIRM で 104.5% を出した。偽物が同じ成績を出すなら、それは成績ではない。

## 4. 組み合わせ馬券にも隙はない（`combo_mispricing.py`）

「単勝・複勝は効率的でも、三連複は市場が正しく合成できていないかもしれない」を
モデル抜きで測った。単勝オッズ→Harvilleで全C(n,3)を合成し、値段帯ごとに全部買う。
7,982R / 三連複 320万組。**控除率25% → 歪みが無ければ全帯75%。**

| 合成オッズ帯 | 三連複ROI (M/V/C) | ワイドROI (M/V/C) |
|---|---|---|
| 1〜4倍 | 97.1 / — / — | 83.4 / 88.3 / 80.7 |
| 6〜10倍 | 84.4 / 102.1 / 83.1 | 78.4 / 76.6 / 84.6 |
| 29〜50倍 | 81.0 / 85.1 / 73.4 | 76.9 / 73.2 / 84.8 |
| 250〜500倍 | 71.4 / 72.4 / 92.0 | 63.5 / 50.8 / 53.8 |
| 2000倍〜 | **44.6 / 22.5 / 36.4** | **21.7 / 3.6 / 3.2** |
| 【全帯】 | 54.0 / 38.8 / 50.8 | 61.9 / 54.1 / 63.1 |

同じ形。安い組は83〜97%、高い組は3〜45%。**100%を超える帯はない。**
「三連複BOXで手広く」が最悪なのはこれで説明がつく — 買い目に高倍率の組が混ざるほどROIが落ちる。

## 7. 残っている唯一の未検証領域

ここまで使った市場情報は**確定オッズ1点だけ**。パリミュチュエルで歪みが残りやすいのは
むしろ**オッズの動き**（＝いつ、どの馬に金が入ったか）で、これはまだ1件もデータが無い。

- `odds_timeline.py` は実装・検査済み（selfcheck ✅）、**8/22の開催日から収集が始まる**。
- 検証に必要なのは「発走2時間前オッズ」と「確定オッズ」の差。
  情報を持つ金は遅く入る、というのがこの種の市場で唯一よく再現される効果。
- 必要サンプルの目安: 1開催日で約350R。**有意な判定には最低でも8〜10開催日（3,000R前後）**。
  つまり結論が出るのは早くて9月中旬。それまでは実弾を増やす理由がない。

これが本当に最後の手持ちカード。ここも駄目なら、
**「手に入る情報の範囲では、控除率を超える方法は無い」が結論**になる。

## 8. それでも明日買うなら（期待値は依然マイナス。その前提で一番マシな形）

1. **単勝120倍超は絶対に買わない**（複勝ROI 47%・単勝38.7%）。
2. **買い目に高倍率の組を混ぜない**。三連複BOXで手広く＝ROIを自分で下げる行為。
   1〜10倍相当の組（＝人気どころの薄い組み合わせ）に絞るほどマシになる。
3. **単勝を、モデル選択の上位4%だけ**（在サンプル98.7%）。点数を増やすほど平均に戻る。
4. **1.0〜1.5倍の複勝が全馬券中いちばん壁に近い（98.1%）**。ただし1点あたりの利幅は
   ほぼ無く、外した1回を取り返せない。資金管理でしか意味を持たない。
5. **紙上運用(paper.py)を止めない**。壁の位置が動くとしたらオッズ動向のデータが溜まった時で、
   その判定には積み上げた記録が要る。

## 再現方法

```bash
cd keiba
python3 rule_roi.py          # 40ルールの実払戻ベタ買いROI       → rule_roi.json
python3 odds_band.py         # オッズ帯別ROIと帯を揃えた残差ROI  → odds_band.json
python3 ev_bet.py            # 期待払戻モデル 第1版              → ev_bet.json
python3 ev_bet2.py           # 第2版(モデル得点と市場のズレ入り)  → ev_bet2.json
python3 combo_mispricing.py  # 三連複/ワイドの値付けのズレ        → combo_mispricing.json
```

検証は全て3分割を厳守（MINE ≤202602 / VALIDATE 202603-05 / CONFIRM 202606-08）。
未知期間は各1回だけ測定。すべての測定に null control（デタラメなデータで同じ手順）を併走。
