# 組合せ馬券オッズ（複勝・ワイド・三連複）の取得メモ

作成 2026-08-18（火・JRA非開催日に検証）／対象コード: `jra_odds.py` / `predict.py` / `harvest_odds_combo.py`

3着内特化システム（複勝・ワイド・三連複）の期待値検証で最大のボトルネックだった
「組合せ馬券のオッズをどう手に入れるか」を、**2経路とも実測で決着させた**。

---

## 0. 結論（3行）

1. **過去レースの組合せオッズ（ワイド・三連複・馬連・馬単・三連単）は netkeiba 公開APIで無制限に遡って取れる。**
   2012年のレースまで確定オッズが返ることを実測。手作業ゼロ。→ `harvest_odds_combo.py`
2. **当日の事前オッズ（1-2分更新）は JRA公式 sp.jra.jp から取れる。** ワイド1リクエスト、
   三連複は「軸馬ページ×(頭数-2)」。netkeiba と全点一致することを検証済み。→ `jra_odds.fetch_official_combo()`
3. **ローカルの `hist_odds/` は本作業で 8,465R すべてが ワイド＋三連複そろい（100%）になった。**
   V8/WF窓の 5,990R も全レース充足。**拡張側の手作業は不要。**

## 1. netkeiba（過去レース遡及）— 本命

### 何が取れるか
`https://race.netkeiba.com/api/api_get_jra_odds.html?race_id=<12桁>&type=<T>&action=init`

| T | 券種 | 過去レース | 備考 |
|---|------|-----------|------|
| 1 | 単勝 | ○ | |
| 2 | 複勝 | ○ | 下限のみ（上限は返らない） |
| 4 | 馬連 | ○ | |
| 5 | **ワイド** | ○ | **下限のみ**（上限は返らない） |
| 6 | 馬単 | ○ | |
| 7 | **三連複** | ○ | |
| 8 | 三連単 | ○ | |

- 1レース7リクエストで全券種。組合せキーの形式は `predict.fetch_jra()` が
  `"1-2"`（昇順ハイフン）/ `"1-2-3"`（昇順）/ `"1>2"`（順序）に正規化済み。**キー形式は正しい**（検証済み）。
- 返る値は**確定（最終）オッズ**。事前オッズではない。

### 遡及可能な範囲（実測 2026-08-18）
| 年 | 結果 |
|----|------|
| 2012 / 2015 / 2017 / 2019 / 2020 / 2021 / 2022 / 2023 / 2024 / 2025 / 2026 | ○ 全券種取得（例: 18頭で wide 153点・三連複 816点） |
| 2010 / 2008 | × `status:NG "empty free odds schedule"` |

- `"empty free odds schedule"` は **(a) その場の無料配信停止 (b) 存在しない race_id** の両方で返る。
  存在する race_id での恒常的な欠落は、hist の実データ 8,465R で **0件**（下記）。
- 実データからの無作為12レース（2023〜2026、各場）を再取得したところ **12/12 成功**、
  かつ **既存の `hist_odds/*.json` と全点一致**（＝APIの値は時間が経っても変わらない・冪等）。

### 収集スクリプト `harvest_odds_combo.py`（新規）
```bash
python3 harvest_odds_combo.py --audit                     # 充足状況の集計だけ
python3 harvest_odds_combo.py --from-hist                 # hist/ にあってオッズ未取得の分
python3 harvest_odds_combo.py --from-hist --repair        # 既存でもワイド/三連複が欠けてる分を取り直す
python3 harvest_odds_combo.py --date 20260816             # その日のJRA全レース
python3 harvest_odds_combo.py --start 20260101 --end 20260331
python3 harvest_odds_combo.py --ids-file ids.txt          # race_id を1行1個
python3 harvest_odds_combo.py 202601010801 202601010812
```
- 出力: `hist_odds/<race_id>.json`（`predict.fetch_jra()` の戻りそのまま。既存形式と互換）
- 既定 **1秒間隔・単一スレッド**、ログインしない、公開APIのみ。
- 1レース1ファイル＋`os.replace` の原子書き込み。Ctrl-C で中断しても取得済みは残り、再実行で続きから。
- 進捗表示（25件ごとに ok/partial/ng/fail/skip と残り時間の見積り）。

## 2. JRA公式 sp.jra.jp（当日の事前オッズ）

### cname 構造（実測で確定）
```
オッズTOP        cname=sw15oli00/FA
 └ 開催(場・日)   sw15orl {2桁} {VV}{YYYY}{KK}{DD} {開催日8桁} /{CHK}
    └ レース×券種 sw15 {T} ou {2桁} {VV}{YYYY}{KK}{DD}{RR} {開催日8桁} Z[..] /{CHK}
```
T = **1**:単勝・複勝 / 3:枠連 / 4:馬連 / **5:ワイド** / 6:馬単 / **7:三連複** / 8:三連単。
**T=2（複勝単独）のページは存在しない** — 複勝は T=1 のページに単勝と同居しており、
既存の `fetch_official()` が `fukuMin`/`fukuMax` として**すでに取得済み**（＝タスクの「T=2」は不要だった）。

### 券種ごとのページ構造
| 券種 | リクエスト数 | HTML | 備考 |
|------|-------------|------|------|
| ワイド T=5 | **1** | `<th class="kumiNo">1-2</th>` + `<div class="wideMin">` / `<div class="wideMax">` | 1ページに全組合せ。**上限も取れる**（netkeibaは下限のみ） |
| 馬連 T=4 | **1** | `<th class="kumiNo">` + `<td class="oz">` | 単一値 |
| 三連複 T=7 | **頭数-2 + 1** | `<th class="kumi">1-2-3</th>` + `<td class="ozzu">` | 開催ページのリンクは `…Z99`＝**軸未選択で表が無い**。そのページの `<select id="jikuuma">` の `<option value="…Z01/FB">` から軸別 cname を拾って順に叩く |

三連複の網羅ロジック: セレクトは出走馬が馬番順に並ぶ。軸=i のページには i を含む全三連複が載るので、
**末尾2頭を除く全軸**を取れば全組合せを網羅できる（どの3頭組も「順番で末尾から3番目以内」の馬を必ず含む）。
馬番に欠番（除外・取消）があっても、番号ではなく**並び順の末尾2つ**を落とす実装にしてあるので正しく効く。

### 実装
```python
from jra_odds import fetch_official_combo
c = fetch_official_combo("202607020811", kinds=("wide", "sanrenpuku"))
# {"wide": {"1-2": 62.9...}(下限), "wide_max": {...}(上限),
#  "sanrenpuku": {"1-2-3": ...}, "umaren": {},
#  "asof": "18:01現在"|"最終"|"確定", "kai_nichi": "2回中京8日",
#  "source": "sp.jra.jp", "reason": None}
```
CLI:
```bash
python3 jra_odds.py 202607020811 --combo                 # ワイド+三連複
python3 jra_odds.py 202607020811 --combo wide --json
python3 jra_odds.py 202607020811 --combo umaren wide sanrenpuku
python3 jra_odds.py 202607020811 --combo --max-axis 2    # 検証用（軸ページ数を絞る）
```
`predict.fetch_jra(race_id, fresh_combo=True)` でも公式の組合せに差し替わる（`combo_source` に出処）。
**既定は OFF**。watch/paper のループを遅くしないため、自動フォールバックは入れていない
（1レース15-20秒かかる）。3着内特化の直前判定を実装するときに明示で渡すこと。

### 検証結果（2026-08-18・非開催日に「直近開催（8/16）」のページで実施）
JRA非開催の火曜でも、**オッズインデックスは直近開催を掲載したままだった**ので実地検証できた。
掲載中: `0120260107 0120260108 0420260207 0420260208 0720260207 0720260208`（＝8/15・8/16の札幌/新潟/中京）

| レース | 券種 | JRA公式 | netkeiba | 不一致 |
|--------|------|---------|----------|--------|
| 202601010801（札幌1R・14頭） | ワイド | 91点 | 91点 | **0** |
| 202601010801 | 三連複 | 364点 | 364点 | **0** |
| 202601010812（札幌12R・14頭） | ワイド / 三連複 | 91 / 364点 | 91 / 364点 | **0** |
| 202607020811（中京11R・16頭） | 馬連 / ワイド / 三連複 | 120 / 120 / 560点 | 120 / 120 / 560点 | **0** |

＝ 点数も値も完全一致（C(n,2)・C(n,3) と一致）。**パーサは正しい。**

### 取れないもの・制約
- **過去日は取れない。** オッズインデックスに載るのは当日＋直近開催のみ。
  過去日を渡すと `reason="開催 2回東京12日 がJRA公式オッズ一覧に無い(当日/前日のみ掲載)。掲載中=[...]"`。
- 三連複はリクエスト数が多い（16頭なら 1+14=15リクエスト、1秒間隔で約20秒）。
  1レースの直前判定には十分だが、全場スキャンには重い。
- `asof` は発売中なら `"18:01現在"`、締切後は `"最終"`、確定後は `"確定"`。

## 3. 遅延について

- netkeiba の API レスポンスに **`data.official_datetime`**（そのオッズの実際の更新時刻）が入っている
  ことを発見した。`predict.fetch_jra()` の戻りに **`odds_time`（最新）と `odds_time_by_type`（券種別）** を
  追加したので、**今後は遅延を推測せず実測できる**。
  - 例: 202601010810 → 全券種 `2026-08-16 15:16:02`（＝そのレースの最終オッズ時刻。過去レースなので遅延0）
- **ライブでの遅延はまだ未計測**（本日8/18は非開催のため）。既知の「単勝で40-50分遅れ」（2026-08-16計測）が
  ワイド・三連複にも同じだけ効くかは、**8/22（土）に下記の手順で必ず実測すること**。
- 実務上の結論は遅延の実測を待たずに確定している:
  **直前（発走30分前以内）の組合せオッズは JRA公式 `fetch_official_combo()` を使う。**
  netkeiba は「40-50分前の値」としてしか信用しない。

## 4. 次にやること

### (A) 8/22（土）に実地でやる ★最優先・15分で終わる
```bash
# 1) 発走30-40分前に、同一レースで両ソースを取って遅延を実測する
RID=<当日の race_id>
python3 -c "
import predict, jra_odds, datetime
o = predict.fetch_jra('$RID')
c = jra_odds.fetch_official_combo('$RID', kinds=('wide','sanrenpuku'))
print('netkeiba odds_time :', o['odds_time'], o['odds_time_by_type'])
print('JRA公式 asof       :', c['asof'], c['kai_nichi'])
print('now                :', datetime.datetime.now())
w = [k for k in c['wide'] if c['wide'][k] != o['wide'].get(k)]
print('ワイド 不一致 %d/%d 点' % (len(w), len(c['wide'])))
print('サンプル:', [(k, o['wide'].get(k), c['wide'][k]) for k in w[:5]])
"
```
確認したいのは3点:
1. `official_datetime` が「今」から何分前か（＝ワイド・三連複の遅延の実測値）。
2. 発売中（`asof="18:01現在"`）のページでもパーサが動くか
   — **今回の検証はすべて `asof="最終"`（締切後）のページ**。発売中はHTMLに
   `oddsJyuBaiMiman` 以外のクラスや「---」表記が混ざる可能性があるので要確認。
3. 除外・取消のある（`<select>` に欠番のある）レースで三連複が全点そろうか
   — 今回は該当レースが無く未検証。実装は並び順ベースで欠番耐性を入れてある。

### (B) 期待値検証の本番（データはもう揃っている）
- `hist_odds/` の 8,465R（うちV8/WF窓 5,990R）× ワイド・三連複オッズで、
  3着内確率モデルの ROI を **全レース比較**で測る。
- RULES.md の鉄則を守ること: ①部分集合ROIで勝ったと言わない ②`rule_audit.py --null-sweep` で
  偽陽性率を測る ③馬場は必須・開催初日は買わない。
- 注意: `hist_odds/` の値は**最終オッズ**。実際に買うのは締切前なので、
  最終オッズでのROIは**やや楽観**（自分の賭けが動かす分＋直前の変動）。
  紙上運用（`paper.py`）で「その時刻の実オッズ」と突き合わせて補正すること。

### (C) 余力があれば
- 複勝の**上限**は netkeiba では取れない（下限のみ）。JRA公式 `fetch_official()` は
  `fuku_max` を返すので、複勝の期待値を上限側でも見たい場合は当日公式を使う。
  過去分の複勝上限は取得手段が無い。
- 三連複の公式取得を高速化したければ、未検証の `sw157ob…`（ボックス）/ `sw157of…`（フォーメーション）
  ページを調べる価値がある（リクエスト数が減る可能性）。今の実装で足りているので優先度は低い。
