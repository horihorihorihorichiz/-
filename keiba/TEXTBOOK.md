# 競馬予想システム 教科書

このプロジェクトで**実際に測って分かったこと**だけで書いた教科書。
一般論や本の受け売りは書かない。全ての主張に、このリポジトリの実測が紐づいている。

対象読者: このシステムを引き継ぐ人／未来の自分／担当するモデル。
読む順: 第1章 → 第6章まで通しで一度。以後は必要な章だけ。

---

# 第1章 この賭けの構造

## 1-1 パリミュチュエルとは何か
競馬は胴元と戦うゲームではない。**買った人全員のカネを集めて、勝った人で山分けする**方式で、
胴元は分ける前に一定割合を抜く。これを控除率という。

**実測した控除率**（本リポジトリで全レース集計）:
```
単勝 20.0% / 複勝 20.4% / 馬連 22.7-22.8% / ワイド 23.3% / 三連複 25.0-25.1%
```
公式値と0.4pt以内で一致。**券種によって10cmずつ深さの違う穴を掘られている**と考えるとよい。

帰結が3つある。
1. **何も考えずに買えば、期待値は必ず 100% − 控除率**。単勝なら80%、三連複なら75%。
2. **勝つとは「控除率を超えること」**。的中率でも配当でもなく、この一点。
3. **払戻は常に確定オッズ**。いつ買っても同じ。「安いうちに買う」は存在しない。
   （※このプロジェクトは一度この誤解をした。第5章5-2を読むこと）

## 1-2 敵は誰か
胴元ではない。**他の全ての購入者が作る「市場」**が敵であり、同時に唯一の教科書でもある。

市場オッズは、何万人もの予想の集約結果。実測すると、これが**とてつもなく正確**:

- 乗り替わりの有無で分けたとき、**実勝率 ÷ 市場想定勝率 = 乗替 0.996 / 継続 1.003**
  （小数点3桁まで市場が正しい。JOCKEY_RAW_REPORT）
- モデルの1位馬の勝率は、市場implied比で **−2.2pt**（V4）。市場の方が上。
- 三連複1-2-3位の的中率: モデル 76.5% < 市場 77.8%（全2,200R・選択バイアス除去済み）

つまり **「市場より正確に予想する」は、正面からやると負ける**。これは願望ではなく測定結果。

## 1-3 勝つ道は原理的に2本しかない
```
(a) 市場より正確に推定する      → 測って負けた（MODEL_V4_RESULT）
(b) 市場の価格ズレを突く         → 未検証。ここが残っている
```
本プロジェクトの1年半は、ほぼ全部が (a) の探索と、その敗北の記録である。
(b) は 2026-08-22 からオッズ時系列の自作収集で着手する。

# 第2章 検証の作法（ここが本体）

**この章が一番重要**。予想の中身より、検証の作法の方がずっと価値がある。
なぜなら**「勝てる」という嘘の数字は、いくらでも作れてしまう**から。

## 2-1 3分割は絶対に動かさない
```
MINE     ≤ 2026-02   決定に使ってよい唯一の期間（閾値・配点・買い方・特徴選択）
VALIDATE 2026-03〜05  一度だけ通す
CONFIRM  2026-06〜08  一度だけ通す
```
**VALIDATE と CONFIRM の両方で合格しなければ採用しない。**

なぜ2期必要か。実測でこうなるから:
- MINEで100%超の案は**いくらでも作れる**（実例多数）
- MINE と VALIDATE の2期で100%超が出ることも**しばしばある**（同日だけで3回起きた）
- **CONFIRM が毎回それを消す**

2期一致は偶然でも起きる。3期一致を要求して初めて、偶然と区別できる。

## 2-2 事前登録（PROTOCOL）を測定の前に書く
何を測るか・合格ラインは何か・試行回数はいくつか を**測る前に**ファイルに書いてコミットする。
書いてから測る。結果を見てから基準を動かさない。

このプロジェクトには PROTOCOL ファイルが十数本ある。全部この順で作られている。
一度、既存の PROTOCOL を上書きしてしまった事故があったが、git 履歴から復元して
正本とし、その経緯を報告書に自己開示した（JOCKEY_RAW_REPORT §1）。**隠さないことが作法**。

## 2-3 多重比較を必ず補正する
100個試して1個が「5%水準で有意」なら、それは**偶然の当たり**。
試行回数を必ず申告し、Bonferroni（有意水準 ÷ 試行数）で判定する。

実例: B-sd22 は VALIDATE +0.823 / CONFIRM +2.644 と**両期プラス**だったが、
プールした z = 2.40 が合格線 2.45（試行7のBonferroni）に **0.05 届かず不合格**。
惜しいから通す、をやらない。

## 2-4 ヌル検査（対照群）を取る
「実力ゼロの偽データ」で同じ採掘をやり直し、偽陽性率を測る。

実例1: オッズ不使用の三連複ルールがROI 164.8%に見えた。偽データでも平均14.8件・
最高ROI中央値236%が出ると分かり**棄却**。この検定をやらなければ実弾に載せていた。

実例2: 当日トラックバイアスの類型が有望に見えたが、グループラベルを1,000回シャッフルすると
**偽の類型でも48.8%の確率で同じ結果が再現**。完全なノイズだった。

## 2-5 選択バイアスを外す
「この条件のレースだけ見ればROI 200%」は無意味。**全レースで比較する**。
部分集合の好成績は、部分集合の選び方に埋め込まれた後知恵でしかない。

実例: コース別に「そのコースで一番良かった買い方」を選んで42コース分並べると
MINE 143.7%。ヌル対照（買い方を無作為に割当）の平均は69.5%。
**差の +74.1pt は全部「選んだこと」によるかさ上げ**で、未知データでは58.5%に落ちた。

## 2-6 後知恵（as-of違反）を仕組みで塞ぐ
人間の注意力では防げない。**コードで塞ぐ**。

このプロジェクトの防御:
- 過去日付・結果同梱データの記帳を既定でブロック（`--allow-past` で明示的にのみ）
- 発走3分前で凍結し、以後は上書き不可（sticky freeze）
- 結果は確定払戻が出た後に自動取得のみ（手入力の経路を作らない）
- 特徴の計算は「そのレース日より前のデータのみ」（as-of設計）
- ルールブックを sha256 で凍結し、起動時に毎回検査

それでも 2026-08-21 の監査で**先読みの穴が4件見つかった**（第6章）。
仕組みで塞いでもなお漏れる。だから**定期的に敵対的な監査をかける**のが最後の砦。

## 2-7 判定の物差し
一次基準は **α（アルファ）**。
市場のlog-oddsをオフセットとして固定した条件付きロジットで、モデルスコアに付く係数。
```
α > 0  ＝ 市場が知らない情報をモデルが持っている
α ≤ 0  ＝ モデルは市場の劣化コピー
```
ROIより先にこれを見る。ROIは分散が大きく、少ない標本では簡単に嘘をつくから。

# 第3章 得点システムの作り方

## 3-1 手作りシステム Ver.99.27 の構造
成分を作って足す。それだけ。
```
S2_Raw = TSI + LTS + FSI + Bonus + DSI + NSI + CSI + WAS + TAS + HCS + NRJA
WAvg   = S2_Raw × 展開乗数
```
| 成分 | 意味 |
|---|---|
| TSI | タイム指数（速さ） |
| LTS | 上がり3F（末脚） |
| FSI | 枠×脚質のマッチ |
| DSI | 距離適性 |
| NSI | クラス実績 |
| CSI | コース適性 |
| WAS | 斤量差 |
| TAS | 道悪適性 |
| HCS | 馬体重 |
| NRJA | レース間隔 |

**この設計思想は正しい**。成分に分けて足す形は、後から配点を学習し直せる。
実際、11成分そのままで配点だけ学習させたら未知データ2期を通過した。

## 3-2 配点は人が決めるな、データに決めさせろ
Ver.99.27 の配点（TSI 30点・DSI 5点 …）は人手で決めたもの。
8,005レースで学習し直すと、**大きくずれていた**:

| 成分 | 現行 | 学習後 | 判定 |
|---|---|---|---|
| DSI 距離適性 | 5点 | **17点相当** | 大幅な過小評価（3.3倍） |
| TAS 道悪適性 | 15点 | **29点相当** | 過小評価（1.9倍） |
| FSI 枠×脚質 | 15点 | **6点相当** | 過大評価 |
| WAS 斤量差 | 15点 | **マイナス** | 逆効果。撤廃すべき |
| HCS 馬体重 / 展開乗数 | — | ほぼ0 | 効いていない |
| TSI / LTS / NSI | 30/30/20点 | ほぼ妥当 | 骨格は正しかった |

**「軽い斤量の馬に加点する」は予想を悪くする**。これは直感に反するが、6条件中5条件でマイナス。

## 3-3 条件別の配点は「芝ダ×距離帯」で切る
コース単位（東京芝2000 など）で切ってはいけない。**7回測って7回とも失敗**した。

決定的な数字:
- 42コースの最適配点を並べると、**同じ競馬場どうし（距離違い）より、
  別の競馬場の同じ距離帯どうしの方が似ている**（4.72 vs 4.48）
- コース単位で自由に配点を変えると、MINEでは的中率+2.9pt だが**未来の2期では下がる**（−1.1pt / −0.5pt）
- 縮小の強さをデータに選ばせると「ほぼ動かすな」が勝つ

正しい粒度は **芝ダ × 距離帯（S/M/L）の6条件**。ここなら未知2期を通過する。
実際の配点表は `SCORE_WEIGHTS_TABLE.md`。要点:

| 成分 | ダS | 芝L | 差 |
|---|---|---|---|
| DSI 距離適性 | 33点相当 | **130点相当** | 4倍 |
| NSI クラス実績 | 32点 | **99点** | 3倍 |
| LTS 上がり | 15点 | **61点** | 4倍 |
| FSI 枠×脚質 | 17点 | 29点（芝Mは**8点**＝最弱） | — |

**芝の長距離は「適性と格」で決まる。ダートの短距離は上がりを見ても無駄。**

## 3-4 出馬表に載っている情報は、もう全部市場が知っている
これが1年半で得た最大の教訓。

全滅した情報源:
```
人が丸めた集計 : 調教評価(p=0.963) / タイム指数 / レビュー原文 / リーディング
生の変化       : 乗り替わり / 斤量前走差 / 馬体重変化 / 間隔（5本ともMINE第1関門すら通らず）
市場の別プール : クロスプール裁定（乖離の86-94%は共通のこちら側の誤差）
```
特に騎手の測定結果は決定的で、**実勝率÷市場想定が0.996と1.003**。
締切前の出馬表に印字される情報は、市場が寸分違わず織り込んでいる。

**唯一 CONFIRM を通過したのは「通過順」** ── レース中に馬がどう動いたかの生データ。
出馬表には載っていない。ここから作った2本が効いた:
- `spd_res`（スピード余力）: 全6条件でプラス（+40〜96点相当）
- `mgn_abs`（着差）: 全6条件でマイナス（−34〜−210点相当）

**教訓: 誰でも見られる情報を綺麗に加工しても勝てない。誰も定量化していない生データを掘れ。**

# 第4章 買い方の設計

## 4-1 的中率とROIは別の戦い
「当たるようにする」と「儲かるようにする」は**別の問題**であり、しばしば逆を向く。

実測: レースを絞って的中率を 46.8% → 83.2%（1.78倍）に上げたとき、
ROI は 78.6% → 91.5%（1.16倍）にしか動かない。**差の分は配当が落ちている**。
市場は「当たりやすいレース」を知っていて、その分オッズを下げているから。

## 4-2 複勝2点には数式で天井がある
82クラスタを横断すると、恐ろしいほどきれいな直線に乗る:
```
ROI = 0.726 × 的中率 + 22.5
```
**的中率を100%まで外挿しても ROI = 95.1%**。
理由は単純で、的中1回あたりの払戻が196〜199円しかなく、投下200円を常に下回るから。
払戻の大きいクラスタ（216円）は例外なく的中率が低い（71%）。トレードオフが完全。

**「全部当てれば勝てる」は、この券種では成立しない。**

## 4-3 券種は7つ全部測れ。ただし勝ち順系は買うな
49名編成で 7券種 × 6条件 × 696案を全数調査した結果:
```
VALIDATE と CONFIRM の両方で ROI100%超・n≥80 を満たした案: ゼロ
```
券種別の傾向:
- **三連単**: MINEで119〜146%が出るが未知データで全滅。数本の大穴的中への過剰適合の見本市
- **馬連・馬単**: 生き残りはタイブレーク1つでCONFIRMが16pt動くほど薄い
- **複勝**: 最も崩れにくい。だから採用しているのであって、絞ったからではない
- **ワイド**: ダート短距離に唯一の3期プラスが残った（第7章 W12）

RULES の「勝ち順系（馬連・馬単・三連単）は買わない」は、この実測に基づく。

## 4-4 順位で買うな、価格ズレで買え（ただし現状はどちらも未達）
**順位ベース**（1位だから買う）は696案全滅。理由: 買い目が市場とほぼ同じになるから。
市場条件付きモデルで測ると、**モデル上位3頭が市場と違うのは312レース中18レース（5.8%）だけ**。
残り294レースは買い目が完全に同一で、ROIが動きようがない。

**EVベース**（確率×オッズが閾値超えの点だけ買う）も全滅。
最も甘い条件でもMINEに100%到達点が存在せず、しかも
**期待値の高い裾ほどROIが下がった**＝EV信号が逆を向いていた。
高EVに見える領域は、市場の値付けミスではなく**モデル自身の過大評価が残っている領域**だった
（reliability検査で予測0.699 vs 実測0.658のズレと一致）。

## 4-5 レースを選ぶのは効く（唯一の確実な武器）
発走前に分かる3つの指標だけでレースを絞る:
```
A: fav_p >= 0.341   市場1番人気の実質確率（固まっているか）
B: ent   <= 1.904   市場の割れ具合（小さいほど意見が一致）
C: sgap  >= 0.066   モデル1位と2位の得点差
```
残るのは全体の約21%。そこでの複勝2点:

| | 的中率 | ROI |
|---|---|---|
| MINE | 94.4% | 92.6% |
| VALIDATE | 95.9% | 95.6% |
| CONFIRM | 92.4% | 85.3% |

**3期とも的中率90%超。**閾値はMINEだけで決めたので、後2期は完全な未知データ。
ただしROIは100%に届かない（4-2の天井）。

# 第5章 データの扱い

## 5-1 データの傷は静かに嘘をつく
実際に起きた事故（全て発見済み・修正済み）:

| 事故 | 症状 | 見つけ方 |
|---|---|---|
| 辞書のタプルキーがpkl保存で文字列化 | 条件別配点が全滅し全体配点にフォールバック | 指紋レースの上位3頭が合わない |
| 着順が馬番でなく0始まりインデックス | 学習が壊れ「重みがマイナス」の偽結果 | 純V3のLL < ゼロ重みのLL（順序が逆） |
| 複勝/ワイドのオッズが[下限,上限]なのに下限だけ保存 | 保守バイアスが測れない | 書式を全件分類して発覚 |
| 自前スクレイパが通過順/ペース/タイム/着差を捨てていた | 最も効く特徴が存在しないことになっていた | 拡張側が手作業で集めた同じデータと突合 |
| 時刻の日跨ぎ（JST 00:00-40だけ自己診断が失敗） | 深夜だけ起動検査が落ちる | 00:27に実際に踏んだ |

**教訓: 検算を必ず入れる。**
- 成分の合計 = 総得点 か（違反0件を全件確認）
- 学習後のLL > 素のLL > ゼロ重みのLL の順になっているか
- 独立に再実装して同じ数字が出るか（誤差1e-11なら一致）
- 指紋（既知レースの上位3頭）が一致するか ← 起動時に毎回自動検査

## 5-2 間違えた考えを潰した記録
**「三連複は発走直前に買うと配当が大きい」は誤り。**
オッズが発走前→確定で中央値1.91倍動くという実測から、一度そう考えた。
パリミュチュエルなので**払戻は買った時刻に関係なく常に確定オッズ**。
正しい解釈は「**判定時に見えているオッズが確定オッズの偏った推定値**」であり、
三連複のEVを約半分に過小評価し、単勝のEVを約3割過大評価している、ということ。

この誤りは検証エージェントが指摘して直った。**自分の思いつきを他人（他のエージェント）に潰させる**のは有効。

## 5-3 集めるべきデータの優先順位
1. **世の中に存在しないデータ** ← 最優先。オッズの時系列がこれ（netkeibaにも無い。自作するしかない）
2. **誰も定量化していない生データ** ← 通過順の全区間。これだけがCONFIRMを通過した
3. **加工済みの指標** ← 全滅。市場が織り込み済み

# 第6章 運用と防御

## 6-1 モデル非依存にする
判定を全部スクリプトに落とす。**モデルは計算しない・上書きしない・出力に従う**。
どのモデルが担当しても同じ判定が出る状態を保つ。

そのための仕組み:
- 起動検査（selfcheck）が15項目を毎回チェック
- **指紋検査** ── 学習配点・発火仕様・ルールブックが1ビットでも変わったら起動時に落ちる
- 検証履歴の読み順を RULES 冒頭に固定 ── 同じ失敗検証を8回目としてやり直さないため

## 6-2 前向き検証が最後の審判
過去データでどれだけ良くても、それは仮説。**未来のレースで実測するまで採用しない。**

- 実弾は停止中。紙上運用で検証
- 候補は掛け金ゼロで記録し、**n≥80 に達するまでROIがいくつでも「検証中」としか表示しない**
  （早まった昇格を仕組みで禁じる。コードにテストが入っている）
- ルールブックは凍結。実測は凍結後の未来レースのみ

## 6-3 定期的に敵対監査をかける
2026-08-21、本番前日に3視点（先読み／データ書式／運用リハーサル）で監査したところ、
**38件の指摘、うち土曜に実害が出るもの12件**が見つかった。仕組みで塞いだつもりでも漏れる。

特に怖かった3つ:
1. 終わったレースが**確定オッズでライブ記帳**されていた（正式コマンドの叩き方そのもので発生）
2. 監視ログが**発走後に再判定してから凍結**していた（順序が逆。実測でT-35の20.0倍がT+20の3.0倍に上書き）
3. オッズが1〜2頭しか取れないと**必ず「最も堅い予想可能レース」と判定**して誤発火する

**監査は「バグを探せ」ではなく「この視点だけで探せ」と分けると見つかる。**

## 6-4 安全のルール（変更不可）

# 第7章 現在地と、残っている道

## 7-1 できていること
- **レースを選べば当たる** ── 複勝2点で的中率 CONFIRM 92.4%（3期再現）
- **並べる力は市場を超えた** ── α>0 が6/6フォールド（V4〜V10は5連敗だった）
- **配点は最適化済み** ── 6条件別、通過順特徴込みで CONFIRM 複勝+5.0pt

## 7-2 できていないこと
**ROI 100%超の常設ルールが無い。** 1,400案以上を測って合格ゼロ。

理由は一言で言える:
> **α > 0 は本物だが、その大きさは市場の 0.16%。**
> 「市場も知っていることを、市場よりわずかに整理して知っている」であって、
> 「市場が知らないことを知っている」ではない。

控除率20〜25%を越えるには、この150倍のエッジが要る。

## 7-3 追跡中の候補（実弾禁止）

| B-sd22（未使用6特徴の追加） | 両期プラスだが z=2.40 < 2.45 | 惜敗 |

## 7-4 残っている唯一の道
**市場の価格ズレ。** 第1章1-3の (b)。

ここまでの全実験は「確定オッズ」という**止まった写真**を相手にしていた。
実際に市場に勝っている人が突いているのは**動き**のはず。
発走前から確定までのオッズ変化を記録したデータは世の中に存在しないので、自作する。

**これが外れたら、控除率を越える手は現時点で無い、と結論する。**
そこまで正直に書いておく。
