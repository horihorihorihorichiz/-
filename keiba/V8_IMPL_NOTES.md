## 2. 追加した特徴の一覧（全22本）

### F1 = 当日トラックバイアス（8本）
「同一開催日・同一場で**当該レースより前に発走した**レースの結果」だけから作る。発走前に確定している
情報なので事前情報として正当。

| 名前 | 種類 | 式 |
|---|---|---|
| `tb_n` | レース単位 | その日その場でここまでに終わったレース数（0-11）。情報量そのものを学習器に渡す |
| `tb_waku` | レース単位 | 先行各レースの「3着内馬の枠番平均 − 出走全馬の枠番平均」（枠番は0-1正規化）の平均。**正=外枠有利** |
| `tb_waku_surf` | レース単位 | 同上を**今日と同じ馬場(芝/ダ)**の先行レースだけで見た値 |
| `tb_front` | レース単位 | 先行各レースの「逃げ・先行タイプの3着内率 − 3/頭数」の平均。**正=先行有利** |
| `tb_front_surf` | レース単位 | 同上の同一馬場版 |
| `tb_upset` | レース単位 | 先行各レースの「勝ち馬の正規化人気 (人気−1)/(頭数−1) − 0.25」の平均。**正=荒れている** |
| `tb_x_waku` | 馬単位 | `tb_waku_surf × (自馬の枠番0-1正規化 − 0.5)`（外バイアスの日の外枠馬が正） |
| `tb_x_ep` | 馬単位 | `tb_front_surf × (0.45 − 自馬の早期位置ep)`（先行有利の日の先行馬が正） |

- **当日3R未満（`tb_n < 3`）では `tb_*` を全て0（中立）**。同一馬場サブセットは2R未満で0。事前登録どおり。
- 枠番は `course.jra_waku(馬番, 頭数)`（既存のJRA枠割当）。
- 早期位置 `ep` は `fit_v2.ep_of` と**同一定義**（過去5走の `corner4/field` 平均、無ければ紙上脚質）。
  写しになっているので `course_bias.py` の自己検証で毎回一致を確認している。

### F2 = 前走不利推定（5本・レース内z標準化）
各馬の `races[0..2]`（直近3走）だけから作る。過去走レコードは定義上すべて事前情報。

| 名前 | 式 |
|---|---|
| `f2_wide_mean3` | 直近3走の `wide` の平均 |
| `f2_wide_max` | 同・最大 |
| `f2_kick_mean3` | 直近3走の `kick` の平均 |
| `f2_kick_max` | 同・最大 |
| `f2_last` | 前走の `wide + kick`（前走で受けた不利の総量） |

```
pos_rel = corner4 / field          # 4角相対位置 (0=先頭)
fin_rel = finish  / field          # 着順相対
wide = max(0, pos_rel − fin_rel) × pos_rel
       # 4角で後方/外にいたのに着順はそれより良い＝ぶん回し・詰まりでの健闘。
       # 位置が深いほど重くするため pos_rel を掛ける（V5の corner_gain は
       # 単なる符号付き差分で、この「深さ加重」と「不利側だけ拾う片側性」が無い）。
kick = max(0, bench − agari) × max(0, fin_rel − 0.35)
       # bench = 同条件(馬場×距離200括り×馬場状態)の平均上がり（as-of）。
       # 条件標準より速い上がりを使ったのに着順が悪い＝展開不利で脚を余した度合い。
       # bench − agari は ±2.5秒でクリップ。
```

- 被覆 89.8%（残りは新馬・未出走で過去走が無い馬。None→レース内zで0＝平均扱い）。
- 実測レンジ: `f2_wide_mean3` p50=0.036 / p95=0.268、`f2_last` p50=0.032 / p95=0.587。

### F4 = コースプロファイル（9本）
コースキー = **場 × 馬場 × 距離帯**（短 <1400 / マイル <1800 / 中長 ≥1800）。実測54キー。

| 名前 | 種類 | 式 |
|---|---|---|
| `cp_n` | レース単位 | `log1p(そのコースの as-of 標本数)` |
| `cp_waku` | レース単位 | そのコースの枠バイアス平均を縮小したもの `Σdev/(n+40)`。正=外枠有利 |
| `cp_front` | レース単位 | 同・脚質バイアス。正=先行有利 |
| `cp_fav` | レース単位 | そのコースの1人気勝率 − 全体1人気勝率（同じく縮小あり）。正=堅い |
| `cp_x_waku` | 馬単位 | `cp_waku × (自馬の枠0-1 − 0.5)` |
| `cp_x_ep` | 馬単位 | `cp_front × (0.45 − ep)` |
| `cs_runs` | 馬単位 | 当該馬の同コース(近似)出走数（0-6でクリップ） |
| `cs_top3` | 馬単位・z | 同上の3着内率（被覆75.2%） |
| `cs_fin` | 馬単位・z | 同上の平均着順割合（符号反転して「大きいほど良い」に統一） |

- 縮小係数 K=40。標本が少ないコースほど値が0（＝バイアス無し）へ寄る。
- `cp_fav` の縮小はグローバル1人気勝率を事前平均にしたベータ縮小。

## 3. リーク対策（ここが本体）

### 3-1. 構造で防ぐ: 「読む→書く」の一方通行
`course_bias.AsOfIndex.build()` は台帳を **日付昇順 → 同一開催日はR番号昇順** に1回だけ走査し、
各レースについて必ず

1. 現在の累積器から特徴を **読んで凍結** し、
2. **その後で** そのレースの結果を累積器に足す

の順で処理する。「全体集計を作ってから自分の寄与を引く」方式は一切使っていない（引き算方式は
標準化・縮小・非線形が絡むと必ず微小リークが残る）。したがって

- **F1**: 同一 `day_key`（race_id先頭10桁＝年+場+回+日）かつ **R番号が小さい**レースだけを見る。
  同日の後続レースは構造的に参照不可能。
- **F4 / F2の上がり基準**: 日付が変わるまで累積器に足さない（`pend` バッファ）ため、
  **当該レースの日付より前の日**のデータだけで作られる。同日の他レースすら入らない。

### 3-2. as-ofの基準を「フォールド境界」ではなく「そのレース自身の日付」にした
指示は「学習フォールドより前の全データから」だったが、実装は**より厳しい**「そのレース自身の日付より前」
を採用した。理由は3つ:

1. フォールド基準だと、同じフォールド内の学習レース同士が互いの結果を（間接的に）見る。
   月次WFでは最大1か月分の同時期リークが残る。日付基準ならゼロ。
2. **学習時とライブ時で情報量の定義が一致する**（RULES.md の統一原則）。ライブでは常に
   「今日より前」しか見えないので、学習も同じ条件に揃える。
3. 実装がフォールドから独立するので、dataset を1回作れば全 variant・全フォールドで使い回せる。

副作用として、コーパス最古日付近の F4 は 0（中立）になる。自己検証で最古日34Rの `cp_n=0` を確認済み。

### 3-3. 結果情報を使う量と使わない量の切り分け
- **結果を使う**のは F1（同日の先行レース）と F4（前日以前のレース）だけ。どちらも当該レースの
  発走前に確定している。
- **F2 は結果情報を一切使わない**。各馬の `races[]`（＝過去走レコード）のみ。上がり基準テーブルだけが
  前日以前のレコード集計で、これも as-of。
- 当該レースの `result.order`（着順・オッズ・人気）は、その **レース自身の特徴には絶対に入らない**。

### 3-4. 独立再計算による検証
`202605021211`（東京 芝2400 18頭・当日11R目）について、`course_bias` を使わない独立実装で
同日の先行10レースから手計算した値と実装値が **1e-9 以内で一致**することを確認した
（`tb_waku=+0.0186 / tb_waku_surf=+0.0517 / tb_upset=-0.1744`）。同日1R目は F1 が全て0。

### 3-5. 定数を「データから決めない」
`NINKI_NEUTRAL=0.25`（荒れ度の原点）は、長期平均を測って決めると「未来を見て決めた定数」になるため、
**固定の事前定数**にしてある。枠バイアス・脚質バイアスはレースごとに自己正規化（3着内の平均 −
出走全馬の平均、実測率 − 3/頭数）しているので、そもそも外部定数を必要としない。

## 6. 既知の限界（正直に）

1. **F1(b)の脚質バイアスは近似**。台帳の `result.order` には各レースの4角通過順が入っていないため、
   「実際に4角3番手以内だったか」ではなく「事前に先行が見込まれた馬か（過去走のcorner4平均／紙上脚質）」で
   代用している。方向は同じだが、実際の逃げ争いの結果は反映されない。
   → 正確にやるなら収穫側でレース結果のコーナー通過順を取る必要がある。
2. **同コース実績は「馬場×距離帯」まで**。過去走レコードに開催場が無く、`vg` も収穫初期の見落としで
   実測91%が2固定（＝信用できない）。場まで一致させたければ収穫の拡張が要る。
3. **F1は当日の先行レースが台帳にある前提**。ライブでは自分で当日結果を集める必要がある
   （`prior_day` 引数）。渡さなければ中立0で動くので事故にはならないが、F1の効果も出ない。
4. **上がり基準テーブルの被覆**。`(馬場, 距離200括り, 馬場状態)` で標本30未満なら
   `(馬場, 距離)` → `(馬場)` に落ちる。道悪の細かい条件は実質 `(馬場, 距離)` で評価されている。
5. **F1は「同一場・同一日」でしか働かない**。開催初日の1-3R、および中央・地方をまたぐ判断には効かない。
6. **効果量は未知**。V4/V5/V7で3回「現有特徴は市場への付加情報ゼロ」が確定している。F1/F2/F4も
   同じ結末になる可能性は十分あり、判定は事前登録の3分割（MINE/VALIDATE/CONFIRM）で1回だけ行う。
   本メモの時点で性能に関する数字は一切出していない（部分集合ROIを先に見て設計を変える事故を防ぐため）。
