「**個別コース（120種）は少なすぎ、汎用（全部込み）は粗すぎる。物理特性でコースを類型化した
"中間の粒度"で学習すれば、市場を条件にした付加情報（α）が増え、期待値プラスになるか**」

前回判明した数字（本書の出発点・`COURSE_REPORT.md` より）:

| 前回の方式 | 結果 | 原因（実測） |
|---|---|---|
| 方式1 素朴（当該コースのみ学習） | 不合格 | 学習データが汎用の 1/23 に減る |
| 方式2 階層（汎用+コース補正） | 不合格（3方式で最良） | 補正が効かない・Δα は MINE窓でゼロ |
| 方式3 重み付け（3〜10倍） | 不合格 | **汎用と1位が 79.7〜90.1% 一致＝特化していない** |
| 窓設計 | — | 100R以上の28コース中 **判定に耐えるのは7**。中山ダ1800(330R)ですら CONFIRM窓 **0R** |

## 1. 変更1: コースを物理特性で類型化する

### 1-1. 類型化の軸（**すべて物理的事実。実データを見る前に確定。出典＝JRA公式コース紹介の
コース図・距離表記および各競馬場の公表値**）

`course.py` にある既存情報（`_JRA_SHIBA_OUTER` = JRA芝の外回り距離集合）は**そのまま流用**する。
それ以外（直線長・坂・回り・1周距離）は course.py に無いので本実験で新規にハードコードする。

**特例（事前登録）**: 新潟芝1000 は直線競走。直線長=1000m → LONG、坂=平坦、回り=直。

## 2. 変更2: 窓設計を「レース数ベースの時系列分割」に変える

### 2-1. 採用した設計と理由

**採用: 時系列順に並べ、レース数ベースで MINE 70% / VALIDATE 15% / CONFIRM 15% に分割。
切れ目は開催日の境界にスナップする（同じ開催日が2つの窓に割れない）。**

「開催回」単位を**採用しなかった**理由:
- JRA の開催回は `(年, 場, 回)` で決まるが、**複数場が同時並行で開催される**ため、
  開催回を単位にすると時系列の順序が一意に定まらない（例: 2東京と2京都が同週に走る）。
- 一方、本実験の学習は**月次ウォークフォワード**（fold月 m のモデルは m より前だけで学習）で
  リークが構造的に排除されている。窓は「どの OOS レースを VALIDATE/CONFIRM と呼ぶか」の
  ラベル付けにすぎず、開催回で括る必要が無い。
- 開催日境界にスナップすれば「同一開催日のレースが窓を跨ぐ」ことは起きない。これで十分。

月次3ヶ月窓を捨てた理由（前回の失敗）: 3ヶ月では季節開催（札幌・函館は夏のみ）が片窓ゼロになる。
レース数ベースなら **VALIDATE 4ヶ月・CONFIRM 3.7ヶ月**に自動で広がり、かつ
本実験の評価単位は個別コースではなく**グループ**（複数場が混ざる）なので季節欠損の影響が激減する。

### 2-2. 確定した分割（**実行前に固定・変更禁止**）

対象 = `course_preds_gen.jsonl` が存在する OOS プール = fold月 202403〜202608 の **6,892R**。
（台帳全体は 7,699R・202307〜202608。202403 より前は GEN の OOS 予測が無いので評価に使えない。）

| 窓 | 期間（開催日） | レース数 | 割合 |
|---|---|---:|---:|
| **MINE** | 20240302 〜 20251221 | **4,810** | 69.8% |
| **VALIDATE** | 20251227 〜 20260425 | **1,048** | 15.2% |
| **CONFIRM** | 20260426 〜 20260816 | **1,034** | 15.0% |

（規則: 累積レース数が 70% / 85% を最初に超えた開催日を、それぞれ VALIDATE / CONFIRM の初日とする。）

**前回比**: 判定に使えるレース数が VALIDATE 551→1,048 / CONFIRM 286→1,034 に増える
（前回は「対象28コースのみ」のプールだった。本実験はグループ＝全レースが必ずどれかに属する）。

## 3. 指標

前回（`COURSE_PROTOCOL.md` §5）と**同一の定義**。同一レース集合・同一市場側で、モデル列だけ差し替える。

1. **α（市場を条件にした付加情報）** — 主指標
   - PLACE: `P(3着内_i) = σ(α·logit q_model_i + β·logit q_market_i + c)`
     q_model = `place_eval.norm_place`（レース内で和3）、q_market = 確定単勝オッズ→控除率補正→Harville（`place_eval.market_probs`）。
   - WIN: `P(1着_i) = σ(α·logit p_model_i + β·logit p_market_i + c)`、p_market = (1/オッズ) を和1に正規化。
   - 推定 `place_eval.fit_logit` / SE は `place_eval.cluster_se`（レース単位クラスタ）。
   - **Δα = α_method − α_GEN**（同一レース集合）。
2. **単勝flat ROI** — 二次基準。モデルスコア1位に100円/レース。払戻は台帳の実払戻。
3. **実オッズ EV 買い（`hist_odds/`）** — 三次基準（§4-3）。
4. **1位一致率**（グループ専用モデルと GEN のスコア1位が一致した割合）— 診断。前回 79.7〜90.1%。
5. **学習レース数 と Δα の関係** — 診断。fold時点のグループ学習レース数でビン分け。

## 4. 判定基準（事前登録・変更禁止）

### 4-0. 判定対象グループ
- 台帳（7,699R）で **100R以上**、かつ **VALIDATE n ≥ 15** かつ **CONFIRM n ≥ 10** のグループのみ。
- 満たさないグループは「判定対象外」として n とともに必ず表に記録する（前回の設計欠陥への対処）。

### 4-1. 一次（付加情報）
水準×方式×目的ごとに、判定対象グループのうち **VALIDATE窓の Δα > 0 となったグループ数 k** を数える。
- 偶然期待 = **G × 0.5**（G = その水準の判定対象グループ数）。
- **合否: 片側二項検定 `P(X ≥ k | n=G, p=0.5) < 0.05` なら「有意に超えた」**。
- 前回のような「月次サブ判定」は行わない（窓と独立でないことが前回判明したため）。
  代わりに **CONFIRM窓の Δα>0 グループ数**も同じ形で報告する（一次の合否には使わない・参考）。

### 4-2. 二次（実弾指標）
グループ単位で **単勝flat ROI が VALIDATE ≥ 95% かつ CONFIRM ≥ 95%**（n は §4-0 の下限）。
- 偶然期待は**モンテカルロ**: 各グループについて「情報ゼロ＝各レースで一様ランダムに1頭選ぶ」を
  **2,000回**反復し `VAL≥95% ∧ CONF≥95%` になる割合 p_g を求め、Σ_g (そのグループの試行数 × p_g)。

### 4-3. 三次（実オッズ EV 買い）
`hist_odds/`（確定前の実オッズ・OOS 6,892R 全件あり）を使い、券種 **複勝・ワイド・三連複** で
- モデル3着内確率 → PL/Harville（`fit_place.trio_probs` / `wide_probs` / `harville_place`）で組合せ確率
- **EV = p_model × 実オッズ**、**EV ≥ 1.2 の点だけ買う**（`place_real.py` の事前登録閾値と同一）
- 払戻は台帳の**実払戻**。1点100円。
- **通過 = VALIDATE ROI ≥ 100% かつ CONFIRM ROI ≥ 100%、かつ 各窓の購入点数 ≥ 50**。
- 目的変数は PLACE のみ（3着内確率が必要なため）。

### 4-4. 総合と多重比較
- **総合通過 = 一次 かつ 二次**（三次は追加情報。三次も通れば「三冠」と別記）。
- 試行数 = Σ_水準 (判定対象グループ数 × 2方式 × 2目的)。実行後の実数を記録する。
- **合否: 総合通過グループ数 < 3 × 偶然期待 なら全体不合格**（前回と同じ 3倍ルール）。

## 5. 既知の限界（実行前に宣言）

1. **VALIDATE と CONFIRM は季節が異なる**（VAL=冬〜春の中山/京都/東京/阪神/中京中心、
   CONF=春〜夏の東京/京都/阪神/福島/新潟/小倉/札幌/函館中心）。時系列分割である以上避けられない。
   グループ単位なので個別コースよりは緩和されるが、「CONFIRM で落ちた」が季節差なのか
   偽陽性なのかは本実験では分離できない。
2. **GEN は前回生成の予測を再利用**する（再学習しない）。データ・特徴・ハイパラ・fold は同一。
3. **GH の学習対象は 202403 以降**（GEN の OOS スコアが必要）。GP より学習期間が短い非対称は限界。
4. **市場側は確定単勝オッズ**（発走直前の実オッズではない）。ただし三次基準だけは `hist_odds/` の
   実オッズを使う。
5. **内/外の決め打ち**（§1-1）。台帳に内外表記が無いため、新潟芝1400・京都芝1400/1600 は
   `_JRA_SHIBA_OUTER` の集合判定で機械的に決める。
6. **スピード指数などの較正定数は全期間フィット**（既存パイプラインの軽微リーク）。全方式共通。
7. **ヌル検査（ラベルシャッフル再学習）は行わない**。二次・三次の偽陽性率はモンテカルロで代替する。
